# channel-subscription-gate Specification

## Purpose

Гарантирует, что регулярные уведомления о новых законах получают только пользователи, подтвердившие подписку на обязательный Telegram-канал продукта, начиная с момента внедрения этого гейта.

## Requirements

### Requirement: Хранение статуса подписки
Система SHALL хранить для каждого пользователя булев статус `channel_verified`. Значение по умолчанию на уровне БД SHALL быть `True` (сохраняет текущее поведение для пользователей, зарегистрированных до внедрения гейта). Регистрация нового пользователя (первый `/start` для ранее не существовавшего `telegram_id`) SHALL явно выставлять `channel_verified = False`.

#### Scenario: Регистрация нового пользователя
- **WHEN** пользователь с ранее неизвестным `telegram_id` впервые нажимает `/start`
- **THEN** создаётся запись `User` с `channel_verified = False`

#### Scenario: Пользователь, зарегистрированный до внедрения гейта
- **WHEN** пользователь уже существовал в БД на момент внедрения этого change
- **THEN** его `channel_verified` остаётся `True` без миграции данных, и гейт на него не влияет

### Requirement: Проверка подписки на канал
Система SHALL проверять членство пользователя в требуемом Telegram-канале через Bot API (`get_chat_member`) по идентификатору канала, заданному в конфигурации. Пользователь SHALL считаться подписанным, если его статус членства — `member`, `administrator` или `creator`. Проверка SHALL выполняться синхронно по явному запросу пользователя (не автоматически в фоне) и SHALL быть оформлена как переиспользуемая функция, не привязанная к одному конкретному обработчику.

#### Scenario: Пользователь подписан на канал
- **WHEN** система запрашивает `get_chat_member` для пользователя и получает статус `member`
- **THEN** `channel_verified` пользователя устанавливается в `True`

#### Scenario: Пользователь не подписан на канал
- **WHEN** система запрашивает `get_chat_member` для пользователя и получает статус `left` или `kicked`
- **THEN** `channel_verified` остаётся `False`, и пользователю сообщается, что подписка не найдена

### Requirement: Кнопка «Проверить подписку»
Система SHALL предоставлять пользователю с `channel_verified = False` кнопку «Проверить подписку», по нажатию на которую запускается проверка из требования «Проверка подписки на канал». При успешной проверке система SHALL показать подтверждение и разблокировать дальнейший шаг онбординга (настройку фильтров). При неуспешной проверке кнопка SHALL оставаться доступной для повторной попытки.

#### Scenario: Успешная проверка по кнопке
- **WHEN** пользователь с `channel_verified = False` нажимает «Проверить подписку» и оказывается подписан
- **THEN** система подтверждает подписку и открывает следующий шаг (настройку фильтров)

#### Scenario: Повторная попытка после неудачи
- **WHEN** пользователь нажимает «Проверить подписку», не будучи подписанным
- **THEN** система сообщает об отсутствии подписки и оставляет кнопку «Проверить подписку» доступной для повторного нажатия

### Requirement: Принудительная проверка подписки перед выполнением команд
Система SHALL проверять `channel_verified` пользователя перед выполнением любого обработчика команды или callback-кнопки бота, если `REQUIRED_CHANNEL_ID` задан в конфигурации. Из этой проверки SHALL быть исключены только обработчики, входящие в сам экран онбординга/подтверждения подписки: `/start`, кнопка «Как это работает?» (`onboarding:example`/`show_example`), и кнопка «Проверить подписку» (`check_subscription`). Исключение `/start` из обёртки не освобождает его от учёта `channel_verified`: обработчик `/start` SHALL сам показывать приглашение подписаться (вместо приветственного сообщения со списком команд) уже зарегистрированному пользователю с `channel_verified = False`. Любой другой обработчик (`/latest`, `/summary`, `/notify_me`, `/settings`, `/help`, кнопки force-summarize и любые будущие команды) SHALL считаться защищённым по умолчанию. Если `channel_verified = False`, защищённый обработчик SHALL не выполнять свою основную логику — вместо этого пользователю показывается то же сообщение с предложением подписаться на канал и кнопкой «Проверить подписку», что и в онбординге. Исключений по ролям (включая `ADMIN_CHAT_IDS`) из этой проверки нет.

#### Scenario: Неподтверждённый пользователь вызывает защищённую команду
- **WHEN** пользователь с `channel_verified = False` отправляет `/latest`, `/summary`, `/notify_me`, `/settings` или `/help`, либо нажимает кнопку «Сделать саммари»
- **THEN** команда/колбэк не выполняет свою основную логику, пользователю показывается сообщение с предложением подписаться на канал и кнопкой «Проверить подписку»

#### Scenario: Подтверждённый пользователь вызывает защищённую команду
- **WHEN** пользователь с `channel_verified = True` отправляет любую защищённую команду или нажимает защищённую кнопку
- **THEN** команда/колбэк выполняется как обычно, без дополнительных сообщений о подписке

#### Scenario: Исключённые обработчики доступны без подтверждения
- **WHEN** новый пользователь (ещё не зарегистрированный) отправляет `/start`, либо любой пользователь нажимает «Как это работает?» или «Проверить подписку»
- **THEN** обработчик выполняется как обычно, без блокировки

#### Scenario: Существующий неподтверждённый пользователь повторно отправляет /start
- **WHEN** уже зарегистрированный пользователь с `channel_verified = False` (пропустивший подтверждение подписки на онбординге) повторно отправляет `/start`
- **THEN** вместо приветственного сообщения со списком команд показывается то же сообщение с предложением подписаться на канал и кнопкой «Проверить подписку», что и на защищённых командах

#### Scenario: Администратор не освобождён от проверки
- **WHEN** пользователь из `ADMIN_CHAT_IDS` с `channel_verified = False` отправляет защищённую команду
- **THEN** команда блокируется так же, как для любого другого неподтверждённого пользователя

#### Scenario: Гейт отключён конфигурацией
- **WHEN** `REQUIRED_CHANNEL_ID` не задан (гейт отключён)
- **THEN** ни одна команда не блокируется независимо от значения `channel_verified`, поведение не отличается от текущего
