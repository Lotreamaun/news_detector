## Purpose

Запросы к GigaChat не должны падать из-за протухшего OAuth-токена: клиент обновляет токен до истечения срока, даже если живёт дольше срока токена, а на неожиданный HTTP 401 один раз берёт новый токен и повторяет запрос.

## Requirements

### Requirement: Токен обновляется до истечения срока
Система SHALL считать OAuth-токен GigaChat действительным до срока, который вернул сервер авторизации, и SHALL получать новый токен не позже чем за 60 секунд до этого срока. Срок, который сервер передал в миллисекундах от эпохи, SHALL учитываться правильно, а не как секунды. Пока токен действителен, система SHALL не запрашивать новый: один клиент получает токен не чаще одного раза за срок его жизни, если не было ответа HTTP 401.

#### Scenario: Цикл планировщика дольше срока токена
- **WHEN** прогон планировщика с OCR идёт 40 минут, а сервер выдаёт токен на 30 минут
- **THEN** после 29-й минуты очередной запрос к GigaChat выполняется с новым токеном, и ни один запрос прогона не получает HTTP 401 из-за протухшего токена

#### Scenario: Токен ещё действителен
- **WHEN** клиент получил токен на 30 минут и через 10 минут отправляет следующий запрос
- **THEN** новый токен не запрашивается, запрос идёт с прежним

#### Scenario: Срок в миллисекундах
- **WHEN** сервер авторизации вернул срок токена в миллисекундах от эпохи (например, `1792011350552`)
- **THEN** токен считается действительным до соответствующего момента (через 30 минут), а не на тысячи лет вперёд

### Requirement: Один повтор запроса после HTTP 401
Если запрос к API GigaChat (генерация, загрузка или удаление файла, список моделей) получил HTTP 401, система SHALL один раз получить новый токен и повторить этот запрос с ним. Повтор SHALL выполняться сразу, без паузы, и SHALL не уступать поток другим ожидающим запросам. Если повторный запрос снова получил HTTP 401, система SHALL вернуть вызывающему коду ошибку без новых попыток, как при любой другой неудаче GigaChat. Другие ошибки (HTTP 400, 403, 402 и прочие) SHALL обрабатываться как раньше. Ошибка самого сервера авторизации (неверный ключ) SHALL не вызывать повтора запроса к API.

#### Scenario: Токен отозван раньше срока
- **WHEN** запрос саммари получил HTTP 401, хотя по сроку токен ещё действителен
- **THEN** клиент получает новый токен, повторяет запрос саммари один раз, и пользователь получает саммари

#### Scenario: Повторный 401
- **WHEN** запрос получил HTTP 401, и повтор с новым токеном тоже получил HTTP 401
- **THEN** третьей попытки нет, вызывающий код получает ошибку, и документ обрабатывается по обычному пути «ошибка GigaChat»

#### Scenario: Повтор не уступает поток
- **WHEN** фоновая оценка важности получила HTTP 401, а в очереди ждёт пользовательский запрос
- **THEN** повтор оценки с новым токеном выполняется до пользовательского запроса, и только потом поток переходит к пользовательскому

#### Scenario: Неверный ключ авторизации
- **WHEN** сервер авторизации отклонил ключ при получении токена
- **THEN** запрос к API не отправляется и не повторяется, вызывающий код получает ошибку авторизации, как раньше

#### Scenario: Новый токен получить не удалось
- **WHEN** запрос к API получил HTTP 401, а получение нового токена завершилось ошибкой (в том числе по таймауту)
- **THEN** запрос к API не повторяется, поток не ставится на паузу, вызывающий код получает ошибку

#### Scenario: 403 не повторяется
- **WHEN** запрос к API получил HTTP 403
- **THEN** новый токен не запрашивается, запрос не повторяется

### Requirement: Обновление токена видно в логе
При получении нового токена система SHALL писать в лог время истечения его срока в читаемом виде (дата и время), а не числом от эпохи. При HTTP 401 от API система SHALL писать в лог предупреждение с адресом запроса о том, что токен обновляется и запрос будет повторён. Сам токен и ключ авторизации в лог SHALL не попадать.

#### Scenario: Новый токен в логе
- **WHEN** клиент получил токен, действующий до 00:55:50
- **THEN** в логе есть строка о новом токене со сроком в виде даты и времени, без значения токена

#### Scenario: 401 в логе
- **WHEN** запрос к API получил HTTP 401
- **THEN** в логе есть предупреждение с адресом запроса об обновлении токена и повторе
