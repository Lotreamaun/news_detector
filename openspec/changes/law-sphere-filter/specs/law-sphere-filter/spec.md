## Purpose
Позволяет пользователю получать только законы интересующих сфер регулирования, классифицируя каждый закон по ключевым словам и целевым формам без LLM.

## ADDED Requirements

### Requirement: Хранение фильтра по сфере
Система SHALL хранить для каждого пользователя множество выбранных сфер (12 категорий, multi-label) с дефолтом «Все сферы». Фильтр SHALL сохраняться между перезапусками.

#### Scenario: Новый пользователь без настройки
- **WHEN** пользователь только зарегистрировался и не проходил визард сферы
- **THEN** система считает его фильтр как «Все сферы включены»

#### Scenario: Сохранение выбора сфер
- **WHEN** пользователь выбрал `[Финансы, Природа]` и нажал «Далее»
- **THEN** система сохраняет только эти две сферы и показывает их при повторном открытии `/settings` → `Сфера`

### Requirement: Классификация статьи по сфере без LLM
Каждая статья SHALL иметь поле `spheres` (CSV/JSON, multi-label), выведенное классификатором по ключевым словам и целевым формам (леммам) без LLM. Классификация SHALL анализировать `title + summary` (fallback первые 1000 знаков `original_text`), лемматизировать, считать вхождения лемм из словарей сфер и присваивать сферу при `score` по уникальным леммам `>=2`, иначе `other`. Допускается 2-3 сферы на статью. Словари SHALL уточняться на реализации, не фиксируются в спеке.

#### Scenario: Финансовая статья распознана
- **WHEN** заголовок содержит «Налоговый кодекс» (леммы `налоговый`, `финансовый`)
- **THEN** `Article.spheres` содержит `finance`

#### Scenario: Многопрофильная статья
- **WHEN** текст содержит леммы из «Финансы» и «IT» (`банк` и `персданные`)
- **THEN** `Article.spheres` содержит обе сферы

#### Scenario: Неизвестная сфера
- **WHEN** ни один словарь не дал `score >=2`
- **THEN** `Article.spheres` содержит `other` и статья считается подходящей только для фильтра «Все»

### Requirement: Фильтрация по сфере
Система SHALL отправлять уведомление и показывать статью в `/latest` только если хотя бы одна `spheres` статьи входит в фильтр пользователя (OR-логика) или фильтр «Все». Фильтр по сфере SHALL комбинироваться с фильтром по силе (AND).

#### Scenario: Уведомление отфильтровано по сфере
- **WHEN** у пользователя фильтр `[Природа]` и пришла статья `spheres=[finance]`
- **THEN** уведомление не отправляется этому пользователю

#### Scenario: Уведомление прошло по сфере
- **WHEN** у пользователя фильтр `[Природа, Финансы]` и пришла статья `spheres=[finance, it]`
- **THEN** уведомление отправляется

#### Scenario: Комбинация сила + сфера
- **WHEN** у пользователя `level=[FZ]` и `spheres=[finance]`, пришла статья `level=FZ` + `spheres=[finance]`
- **THEN** уведомление отправляется; если хотя бы один из фильтров не совпал — не отправляется

### Requirement: Онбординг-визард шага «Сфера»
Визард SHALL показывать шаг «Сфера» как 12 toggle-кнопок Inline (`[Природа ☑] ...`), кнопки `[Выбрать всё]` и `[Далее]`, состояние SHALL сохраняться между нажатиями. Визард SHALL вызываться как шаг 1/3 онбординга (после приветствия, до «Сила») и из `/settings` → `Сфера`, с опцией `Пропустить → Все`.

#### Scenario: Новый пользователь выбирает сферы
- **WHEN** новый пользователь на шаге «Сфера» нажал `[Финансы]` (toggle) и `[Далее]`
- **THEN** система сохраняет фильтр `[Финансы]` и переходит к шагу «Сила»

#### Scenario: Пропуск сферы
- **WHEN** пользователь нажал `Пропустить → Все` на шаге «Сфера»
- **THEN** фильтр остаётся «Все сферы»

#### Scenario: Повторная настройка сферы
- **WHEN** пользователь вызвал `/settings` → `Сфера`
- **THEN** показываются те же 12 кнопок с текущими ☑/☐
