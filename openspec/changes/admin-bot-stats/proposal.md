## Why

Чтобы понять, живы ли бот и его аудитория, администратору сейчас приходится читать логи: в БД хранится только текущее состояние (кто зарегистрирован, какие акты приняты), а действия пользователей — команды, кнопки, открытия Mini-App, блокировки — нигде не записываются. Нужна статистика прямо в админ-панели: «пульс» (что происходит сейчас) и «тренд» (растём или теряем по неделям), без похода в логи.

## What Changes

- **Журнал событий.** Новая таблица `events` (`at`, `kind`, `telegram_id` — пусто у системных событий, `ref`). События пишутся в момент, когда происходят, а не периодической задачей. Запись событий никогда не ломает основной поток: при сбое пишется предупреждение в лог, а команда, уведомление или проверка продолжаются.
- **Что записывается:**
  - аудитория: регистрация, прохождение гейта канала, блокировка и разблокировка бота (по апдейту Telegram `my_chat_member` — с точным временем, а не по ошибке 403 при рассылке);
  - активность: каждая команда и нажатие кнопки (единая точка перед всеми обработчиками), изменение фильтров, открытие Mini-App (закон / дайджест / «Все за сегодня»);
  - саммари по запросу: запрос, результат (готово / нет текста / отказ / ошибка), упор в месячный лимит;
  - доставка: отправленное и неотправленное уведомление (закон / дайджест / недельная подборка);
  - конвейер: итог каждой проверки pravo.gov.ru (успех со счётчиком новых актов или сбой), обработка акта (откуда текст — страница / OCR / нет; чем кончилось саммари), отправка недельной подборки.
- **Mini-App сообщает об открытии.** Страница при загрузке отправляет подписанную `initData`, поэтому открытие привязывается к конкретному пользователю. Открытия вне Telegram (без `initData`) не считаются.
- **Вкладка «Статистика» в админ-панели** с переключателем:
  - **Пульс** — «сегодня» и «7 дней» (по Москве): подписчики, новые, заблокировавшие, активные пользователи, открытия Mini-App, саммари по запросу, упоры в лимит за месяц, доставленные уведомления; здоровье конвейера (последняя проверка, акты за сутки по источнику текста и исходу саммари); распределение фильтров уровней; лента последних событий. Пока вкладка открыта и видна, Пульс обновляется раз в минуту.
  - **Тренд** — по неделям (12 или 52 недели): регистрации и блокировки, активные за неделю, открытия Mini-App, саммари по запросу, доставленные уведомления, принятые акты и акты с саммари, сбои проверок, отправка недельной подборки. Регистрации и акты строятся по всей истории (`users`, `articles`); метрики из журнала показываются начиная с первого записанного события, а более ранние недели помечаются «нет данных», а не нулём.
- **Администраторы исключаются из метрик** (по текущему `ADMIN_CHAT_IDS` при подсчёте, а не при записи). В ленте их события видны с пометкой.
- **Цифры считаются по запросу**, когда открыта панель. Отдельной задачи предрасчёта и таблицы агрегатов нет.
- **Хранение:** события старше 365 дней удаляются отдельной суточной задачей.
- **Доступность панели расширяется.** Сейчас панель (и вход в неё) подключается только при доступной модерации, для которой нужен `WEEKLY_DIGEST_TIME`. Теперь панель со статистикой доступна при заданных `WEBAPP_URL` и `ADMIN_CHAT_IDS`; вкладка модерации подборки, как и раньше, требует ещё и `WEEKLY_DIGEST_TIME`.
- **`/admin` — полноценный вход в панель.** Ответ на `/admin` оформлен как пятничное напоминание: пометка «служебное» и, если модерация доступна, сводка подборки (когда уйдёт, сколько законов, сколько важных без саммари, сколько не оценено). Дальше одноразовая ссылка для браузера (как сейчас) и кнопка «📋 Открыть панель», которая открывает Mini-App. При выключенной подборке сводки нет, остаются ссылка и кнопка. Сейчас `/admin` в этом случае отвечает «Панель модерации недоступна», а теперь ведёт в статистику.

## Capabilities

### New Capabilities
- `bot-activity-stats`: журнал событий (что, когда и откуда пишется; устойчивость к сбоям записи; хранение 365 дней), сообщение Mini-App об открытии, вкладка «Статистика» в админ-панели (Пульс, Тренд, лента, исключение администраторов, автообновление, «нет данных» до начала журнала).

### Modified Capabilities
- `weekly-digest-moderation`: «Модерация недоступна без условий» — без `WEEKLY_DIGEST_TIME` панель больше не пропадает целиком: она открывается со статистикой, а модерация подборки остаётся недоступной (напоминание не шлётся, подборка уходит автоматически). «Вход по магической ссылке» — ответ на `/admin` содержит сводку подборки (при доступной модерации), ссылку для браузера и кнопку Mini-App.

## Impact

- Код:
  - новые `app/models/event.py` (модель `Event`), `app/services/events.py` (`record_event` — безопасная запись) и `app/services/stats.py` (запросы Пульса, Тренда и ленты);
  - `app/main.py`: обработчик активности в группе `-1`, обработчик `my_chat_member` и суточная очистка журнала;
  - `app/bot/handlers.py`: регистрация, гейт, фильтры; ответ на `/admin` (сводка, ссылка, кнопка Mini-App, новое условие доступности);
  - `app/services/force_summary.py`: запрос и исход саммари, упор в лимит;
  - `app/services/scheduler.py`: доставка, итог проверки, обработка акта, недельная подборка; общий построитель строк сводки подборки для напоминания и `/admin`;
  - `app/webapp/server.py`: `POST /seen` и вызов из страницы Mini-App;
  - `app/webapp/admin.py`: `GET /admin/api/stats`, `GET /admin/api/meta`, новые условия подключения панели;
  - `app/webapp/static/admin.html`: вкладки «Подборка | Статистика», Пульс и Тренд.
- БД: новая таблица `events` с индексами по `at` и `(kind, at)`, создаётся через `create_all`; существующие таблицы не меняются.
- API: `GET /admin/api/stats?view=pulse|trend&weeks=12|52` и `GET /admin/api/meta` (доступна ли модерация) — только для администраторов, та же авторизация, что у остальных `/admin/api/*`. `POST /seen` — для Mini-App, с проверкой `initData`, отвечает без данных.
- Зависимости: новых нет. Графики рисуются средствами страницы (CSS и inline SVG), без библиотек.
- Вне объёма: реактивация пользователя при возврате (issue #23 — обработчик `my_chat_member` из этого change станет для неё естественным местом), уведомления администратору со статистикой, экспорт статистики, факт прочтения уведомлений (Telegram его не сообщает), ретроактивное восстановление активности из логов, когортный анализ удержания.
