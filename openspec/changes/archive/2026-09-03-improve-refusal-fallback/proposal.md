## Why

Фолбэк на отказ LLM (GigaChat) в саммари/OCR ещё ненадёжен: детектор `looks_like_refusal` ловит лишь часть формулировок отказа, а при промахе пользователю уходит «лонгрид» с текстом дисклеймера вместо выжимки. Опыт показывает GigaChat перефразирует отказ (дисклеймер про «не обладает собственным мнением», «чувствительные темы» и т.п.) десятками способов, и вручную расширять список маркеров бесконечно нельзя. Нужно ловить 70–80% отказов и вместо сырого текста отказа отправлять пользователю аккуратное уведомление-фолбэк.

## What Changes

- **Повышение полноты детекции отказа**: перейти от хэнд-шейпанного списка маркеров к более устойчивой эвристике, которая распознаёт отказ в разных синонимичных формулировках (не только перечисленные ранее фразы), не увеличивая ложные срабатывания на настоящих саммари.
- **Красивое уведомление-фолбэк**: при распознанном отказе вместо текста дисклеймера пользователь видит понятное уведомление (например, «Не удалось сформировать саммари, текст может быть недоступен» + ссылка на оригинал), а в БД статья сохраняется без текста отказа.
- Поведение применяется ко всем путям генерации саммари/текста: фоновый daily, кнопка «Сделать саммари», `/summary`, OCR.
- **BREAKING**: нет — только повышение качества фолбэка; схема БД и API не меняются.

## Impact

- `app/services/gigachat.py` — заменить/расширить `looks_like_refusal` на устойчивую эвристику (маркеры + правила полноты).
- `app/services/summarizer.py` — при отказе вызывать единый обработчик фолбэка (бросить `GigaChatError` как сейчас), чтобы вызывающий код показал красивое уведомление.
- `app/services/rss_parser.py` — `ocr_document_text`: отказ → `None` (без мусора).
- `app/bot/handlers.py` / `scheduler.py` — точки, где при отказе формируется уведомление-фолбэк пользователю.
- Тесты/проверка на наборе реальных формулировок отказа GigaChat.
- Без новых зависимостей; без изменения БД и API.
