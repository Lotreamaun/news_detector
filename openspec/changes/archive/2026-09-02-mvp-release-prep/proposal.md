## Why

Проект переходит в прод как MVP. Накоплен dev-мусор (/test, /notify_me, /my_id, спам всеми пропущенными законами на старте) и незавершённая логика /latest (сейчас показывает последние ОБРАБОТАННЫЕ законы без учёта подписок, с саммари). Для нового пользователя с пустой лентой это бесполезно, а спам на старте и тестовые команды создают шум перед релизом. Нужно почистить прод-поверхность, сделать /latest подписочно-ориентированным (10 последних по фильтрам, без саммари, только заголовок+ссылка) и актуализировать приветствие.

## What Changes

- **BREAKING**: Удалить dev-команды `/notify_me`, `/my_id`, `/test` и хендлеры/регистрации/кнопки, связанные только с тестом (поиск по проекту на `notify_me`, `myid`, `test_gigachat`, `TELEGRAM_PROXY` остаётся).
- Проинспектировать проект на другие тестовые артефакты (мок-переменные `OCR_TEST_EONUMBERS`, временные хуки, `TELEGRAM_PROXY` остаётся для прод-нужд, но проверить) — удалить.
- **BREAKING**: Изменить `/latest`: вместо «последние 10 обработанных» → «10 последних за последние 30 дней в хронологическом порядке по подпискам пользователя» (учитывает `law-force-filter`/`law-sphere-filter`/`law-region-filter`; для нового пользователя без настройки дефолт — `[Конституция, ФКЗ, ФЗ]`, а не «Все», с подсказкой в онбординге «например, юристу по крипте — оставь только ФЗ»), заголовок сообщения «Законы за последние 30 дней», `published_at >= now-30d`, `ORDER BY published_at DESC`. Без саммари: только заголовок + ссылка (MUST NOT показывать саммари). Для нового пользователя без законов — пустой ответ «Пока нет законов за последние 30 дней по вашим фильтрам» + подсказка `/settings`.
- Лимит `/summary` 10/мес **не распространяется** на Конституцию/ФКЗ/ФЗ — они саммаризируются автоматически в фоне без кнопки (расширение `is_important`).
- Фолбэк при недоступности GigaChat/pravo: без саммари + ссылка, не падать; Telegram `429 Too Many Requests` → `sleep`+`retry`, `403 Bot blocked` → `is_active=False` (критично при росте до 100+ юзеров, для MVP 10 юзеров — терпимо, но заложить).
- Убрать спам всеми пропущенными законами на старте: на первом запуске после деплоя НЕ рассылать 100+ уведомлений о старых законах; обрабатывать только новые, появившиеся после старта (флаг `initial_sync_done` или отметка `last_checked`).
- Актуализировать приветственное сообщение `/start`: коротко ценность (“Присылаю саммари новых законов по твоим фильтрам”), что дальше (`/latest` → 10 по подпискам, `/settings` → фильтры, `/help`), без упоминания «в разработке», + Inline-кнопка `[🔍 Показать пример уведомления]` → шлёт тестовое уведомление как в проде (один из последних ФЕДЕРАЛЬНЫХ ЗАКОНОВ, FZ, с кнопками «Сделать саммари»/«Полный текст») чтобы сразу показать как выглядит уведомление и фишки.
- **BREAKING**: Обновить `/help` — убрать dev-команды, оставить только прод-команды.
