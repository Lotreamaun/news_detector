## Why

Кнопка «Как это работает?» на `/start` показывает тестовое уведомление, выбирая
реальный `ФЗ` за последние 30 дней из БД. Если за это окно не спарсено ни
одного `ФЗ`/`ФКЗ` (случается — источник иногда не даёт документов нужного
уровня несколько дней подряд), новый пользователь вместо демонстрации пользы
продукта видит `«Пока нет законов для примера. Попробуйте позже: /latest»` —
худший возможный первый экран для только что зарегистрированного человека.
Нужен гарантированный fallback: заранее подготовленный реальный закон,
который всегда доступен для демо-показа, независимо от состояния парсинга.

## What Changes

- Добавить в БД одну заранее подготовленную статью-пример: реальный ФЗ за
  2026 год, с полным текстом (через существующий пайплайн получения текста)
  и саммари (через существующий `Summarizer`), помеченную отдельным флагом
  как демо-статью (не результат парсинга ленты).
- Она гарантированно попадает в БД на проде через идемпотентную проверку при
  старте приложения (по аналогии с существующим `needs_backfill`) —
  вставляется один раз, если ещё не существует.
- `_send_example_notification` (флоу «Как это работает?») использует эту
  статью как последний fallback-уровень, когда в БД нет ни одного реального
  `ФЗ`/`ФКЗ`/`Конституция` за 30 дней — так фолбэк-сообщение
  «Пока нет законов для примера» перестаёт быть достижимым в проде.
- Демо-статья исключается из `/latest`, чтобы обычные пользователи не видели
  её вперемешку с настоящими законами.
- Демо-статья вставляется без рассылки уведомлений существующим подписчикам
  (не проходит через `scheduler`/`_notify_users`).

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `onboarding-flow`: добавляется требование о гарантированном fallback на
  подготовленную демо-статью, когда в БД нет подходящего реального закона за
  30 дней для показа по кнопке «Как это работает?».
- `bot-handlers/latest`: `/latest` дополнительно исключает демо-статью из
  выдачи (список остаётся только из реально спарсенных законов).

## Impact

- `app/models/article.py` — новое поле `Article.is_demo` (bool, default
  `False`).
- `app/main.py` — новый идемпотентный шаг при старте, добавляющий демо-статью,
  если её ещё нет (по аналогии с `_run_initial_check`/`needs_backfill`).
- `app/bot/handlers.py` — `_send_example_notification` (доп. fallback-уровень
  на демо-статью) и `/latest`-обработчик (исключение `is_demo` из выборки).
- Одноразовая подготовка контента демо-статьи (конкретный ФЗ 2026 года, его
  текст и саммари) — на этапе `design.md`/`tasks.md`.
- SQLite: существующие БД на проде уже имеют таблицу `articles` без колонки
  `is_demo` — потребуется безопасное добавление колонки без миграционного
  фреймворка (см. `design.md`).
