## Why

В WebApp-дайджесте неудача «Сделать саммари» сообщалась мелкой серой строкой под кнопкой, которую легко не заметить, а кнопка сразу снова была доступна. Пользователи нажимают повторно, и GigaChat отвечает `429 Too Many Requests` — в том числе на запросы других пользователей по тому же документу. Плашка «Содержание этого закона пока недоступно» была красной, как ошибка, хотя это нормальное состояние (портал ещё не выложил текст), а в тёмной теме Telegram светлые плашки слепили или сливались с фоном. Исправление уже реализовано (`app/webapp/server.py`); этот change приводит спеки к фактическому поведению.

## What Changes

- Любой неуспешный исход «Сделать саммари» показывается заметным баннером-уведомлением сверху экрана (стиль плашки ошибки), который скрывается сам через несколько секунд или по нажатию; на устройствах с поддержкой — с вибрацией Telegram.
- После временной неудачи (текст не получен, сбой, обрыв ответа) повтор по кнопке доступен только через 60 секунд: кнопка остаётся видимой, но приглушена; нажатие в это время не отправляет запрос, а показывает баннер «Попробуйте позже.» с живым обратным отсчётом «Повторить можно через N сек.».
- Сервер после временной неудачи по документу 60 секунд отвечает на повторные запросы по нему исходом «кулдаун» (с оставшимся временем), не обращаясь к языковой модели, — для любого пользователя и после перезагрузки страницы.
- Строка статуса под кнопкой остаётся только для окончательных исходов (лимит исчерпан, модель отказалась — кнопка исчезает) и для ситуаций, требующих действия пользователя (устаревшая сессия, страница открыта вне Telegram); разовые неудачи сообщает только баннер.
- Плашка «Содержание этого закона пока недоступно» становится нейтральной (в цветах темы Telegram); красный цвет — только для ошибок и баннера. Плашки состояния, ошибки, саммари и баннер имеют единую типографику (14px, интерлиньяж 1.5) и геометрию.
- Тёмная тема Telegram: приглушённые варианты дисклеймера «Текст распознан с помощью ИИ», красных плашек и баннера, заметная рамка нейтральной плашки; смена темы применяется без перезагрузки.

### Modified Capabilities
- `digest-notifications`: требование «Кнопка „Сделать саммари“ в секции WebApp-дайджеста» — баннер вместо сообщения на месте кнопки для разовых неудач, кулдаун повторной попытки, строка статуса только для окончательных исходов.
- `force-summarization`: требование «Принудительная саммаризация из WebApp-дайджеста» — новый исход «кулдаун» после временной неудачи по документу, без вызова языковой модели.
- `content-viewing`: новое требование к оформлению плашек WebApp (нейтральная плашка «текст недоступен», единая типографика, тёмная тема).

## Impact

- Код: `app/webapp/server.py` — HTML/CSS/JS страницы Mini-App (баннер, кулдаун на клиенте, стили плашек, тёмная тема) и `handle_summarize` (серверный кулдаун, исход `cooldown` с `retry_after`). Уже реализовано и проверено в headless-браузере и тестовым клиентом aiohttp; остаётся проверка в живом Telegram.
- API: `POST /summarize` может вернуть `{"status": "cooldown", "retry_after": N, "message": …}` (200). Других клиентов, кроме страницы Mini-App, у эндпоинта нет.
- Состояние: словарь последних неудач по `external_id` в памяти процесса (`app["summarize_failed_at"]`), сбрасывается при рестарте — без изменений БД и конфигурации.
- Лимиты пользователей не меняются: неудачи и кулдаун лимит не расходуют.
