## Context

См. proposal.md — Why. Текущее состояние, на которое опирается решение:

- Страница Mini-App — один HTML с встроенными CSS и JS, который отдаёт `handle_app` в `app/webapp/server.py`; тот же файл обслуживает `GET /full_text` и `POST /summarize`. Одна страница работает в двух режимах: одиночный просмотр (`?external_id=`) и дайджест (`?ids=`).
- `POST /summarize` вызывает `force_summarize` (`app/services/force_summary.py`); месячный лимит пользователя списывается только при успехе, поэтому неудачи бьют не по пользователю, а по квоте GigaChat (OCR — это загрузка PDF и запрос к модели).
- Цвета темы Telegram страница получает через CSS-переменные `--tg-theme-*`, которые выставляет `telegram-web-app.js`; схема (`light`/`dark`) доступна как `Telegram.WebApp.colorScheme`, смена — событием `themeChanged`.
- Плашки до правки: дисклеймер 14px/1.6, «текст недоступен» (`.error`) 16px/1.6 с отступом 12px, саммари 14px/1.5 с отступом 8×10px; у дисклеймера и `.error` фиксированные светлые цвета без тёмных вариантов.

## Goals / Non-Goals

**Goals:**
- Неудачу саммаризации нельзя не заметить, а повторные нажатия не превращаются в поток запросов к GigaChat.
- Защита от 429 работает и при перезагрузке страницы, и при запросах разных пользователей по одному документу.
- Цвет плашки передаёт смысл: красный — «что-то пошло не так», нейтральный — «так и должно быть сейчас».

**Non-Goals:**
- Ограничение частоты запросов на пользователя или глобальный rate limit к GigaChat.
- Обрезка саммари по границе предложения (отдельная правка спеки саммари).
- Показ дисклеймера «распознано ИИ» только для OCR-текстов (сервер не знает источник текста — отдельная задача).
- Кулдаун в боте (кнопка «Сделать саммари» в чате, `/summary`) — там поток повторов ограничен иначе.

## Decisions

1. **Кулдаун на двух уровнях.** Клиент: после временной неудачи карточка запоминает момент окончания кулдауна (60 с или `retry_after` от сервера), кнопка получает приглушённый стиль, клик в это время не шлёт запрос и показывает уведомление. Сервер: `app["summarize_failed_at"]` — словарь `external_id → time.monotonic()` последней неудачи `no_text`/`error`; повторный запрос по документу раньше 60 с получает `200 {"status": "cooldown", "retry_after": N, "message": …}` без вызова `force_summarize`. Клиентского кулдауна мало: он теряется при перезагрузке страницы и не знает о других пользователях; серверного мало для UX: без клиентского пользователь узнаёт о задержке только после запроса. Проверка кулдауна идёт после проверки подписи и подписки, чтобы неавторизованные запросы получали прежние 401/403.

2. **Кулдаун по документу, а не по пользователю.** Причина неудачи — свойство документа (текста ещё нет на портале, PDF не распознаётся, GigaChat перегружен), а не пользователя; повтор того же документа другим пользователем через 5 секунд почти наверняка закончится так же. Успех и окончательные исходы (`ok`, `limit`, `refused`) удаляют запись. Альтернатива — ключ `(user, external_id)` — отвергнута: не защищает от 429 при одновременном интересе нескольких пользователей к свежему документу.

3. **Состояние в памяти процесса.** Словарь без TTL-очистки: по одной записи на документ с неудачей, записи снимаются успехом; за время жизни процесса это сотни строк максимум. После рестарта кулдаун сбрасывается — допустимо (KISS, без таблицы и миграции).

4. **Уведомление переиспользует стиль `.error`.** Элемент `<div id="toast" class="error toast">`: внешний вид (цвета, рамка, кегль 14px, интерлиньяж 1.5, отступ 8×10px, скругление 8px) задаёт `.error`, а `.toast` — только фиксированное положение сверху (с учётом `safe-area-inset-top`), тень и анимацию появления. Так уведомление и плашки ошибок не могут разойтись по стилю. Показ — 6 с, повторный показ перезапускает таймер, нажатие скрывает; `HapticFeedback.notificationOccurred('error')`, если доступен. Обратный отсчёт — `setInterval` раз в секунду, пока уведомление видно; по истечении кулдауна строка меняется на «Можно повторить.». Альтернатива — `Telegram.WebApp.showAlert` — отвергнута: модальное окно блокирует страницу и не умеет живой отсчёт.

5. **Где показывать причину.** Окончательные исходы (`limit`, `refused`) — строка статуса на месте исчезнувшей кнопки (постоянная причина) плюс уведомление; временные — только уведомление, без строки (иначе одно и то же сказано трижды: уведомление, строка и плашка «текст недоступен»). Устаревшая сессия и открытие вне Telegram — строка и уведомление: пользователю нужно действие.

6. **Нейтральная плашка — отдельный класс `.unavailable`.** Общая геометрия задаётся одним правилом `.error, .unavailable { … }`, цвета — раздельно; `.unavailable` берёт `--tg-theme-secondary-bg-color` и `--tg-theme-text-color`. Ошибки загрузки и «не переданы документы» остаются `.error`. Альтернатива — перекрасить `.error` — отвергнута: настоящие ошибки тоже стали бы нейтральными.

7. **Тёмная тема по `Telegram.WebApp.colorScheme`, а не по `prefers-color-scheme`.** Скрипт ставит класс `dark` на `<html>` и обновляет его по `themeChanged`; тёмные варианты — правила `.dark .disclaimer`, `.dark .error`, `.dark .unavailable` (заметнее рамка), `.dark .toast` (плотнее тень). Цвета — приглушённые варианты тех же оттенков (тёмно-бордовый фон с розово-красным текстом, тёмно-янтарный с жёлтым). Медиа-запрос ОС отвергнут: вне Telegram фон страницы всегда светлый (нет `--tg-theme-bg-color`), и тёмные плашки на белом фоне выглядели бы чужеродно; внутри Telegram тема приложения может не совпадать с темой ОС.

## Risks / Trade-offs

- [Кулдаун по документу блокирует повтор и тому, кто не нажимал] → 60 с — короткий срок, уведомление сразу говорит, сколько ждать; по другим документам ограничения нет.
- [Неудача от сбоя посредника (обрыв ответа) на сервере не фиксируется] → клиентский кулдаун всё равно применяется; если сервер успел сохранить саммари, перепроверка `/full_text` его покажет.
- [Несколько процессов сервиса не делят словарь кулдауна] → сервис работает одним процессом (см. спеку `deployment`); при масштабировании защита ослабнет, но не сломается.
- [Уведомление сверху на 6 с закрывает дисклеймер и значок «Beta»] → временно и скрывается по нажатию.

## Migration Plan

Изменение только в `app/webapp/server.py`, без БД и конфигурации: деплой новой версии, откат — предыдущей. Старые открытые страницы (кешированный HTML) получат от сервера `status: "cooldown"`, который не знают: они покажут сообщение из поля `message` на месте кнопки и оставят кнопку — поведение остаётся корректным.
