## Why

Оценки важности ставит GigaChat, и на эталоне граница «важно / нейтрально» верна лишь в 74–92% случаев; кроме того, часть актов остаётся без саммари (отказы модели). Пока недельная подборка уходит всем подписчикам автоматически, любая ошибка модели доходит до пользователей. Администратору нужен короткий этап проверки перед рассылкой — достаточно удобный, чтобы он реально им пользовался, и не ставящий под угрозу пятничную регулярность рубрики.

## What Changes

- **Напоминание администраторам.** В пятницу в `WEEKLY_REVIEW_TIME` (по умолчанию `12:00`, в `WEEKLY_DIGEST_TZ`) бот шлёт **только администраторам** (`ADMIN_CHAT_IDS`) служебное сообщение: сколько законов в подборке, у скольких нет саммари, сколько не оценено, сколько времени до отправки. Две кнопки: открыть панель (Mini-App) и «🔗 Ссылка для браузера». Сообщение отправляется напрямую по списку администраторов, а не через рассылку пользователям, поэтому обычные подписчики его не получают. Напоминание одно, без повторов.
- **Админ-панель** (отдельный модуль `app/webapp/admin.py`, оформление — из существующего Mini-App) в двух режимах:
  - Mini-App в Telegram (вход по подписанной `initData`, доступ — только `ADMIN_CHAT_IDS`);
  - обычный браузер на компьютере: команда `/admin` или кнопка из напоминания присылает одноразовую «магическую» ссылку, которая обменивается на сессию в cookie.
- **Что делает администратор в панели:**
  - переключателем «в подборке / нет» включает и исключает законы, в том числе закон с оценкой ниже «важно» или ещё не оценённый; решение администратора окончательно, модель его не пересматривает;
  - для актов без саммари: делает его через GigaChat или пишет вручную; любое саммари можно отредактировать (в том числе исправить оборванное «…»);
  - копирует текущий набор одной кнопкой «Скопировать Markdown» (название, саммари, ссылка) — основа для ручного поста в Telegram-канал, который пишется до отправки подборки.
- **Согласования нет.** Панель всегда показывает ближайшую неотправленную подборку, её можно править всю неделю до начала отправки; в пятницу в запланированное время уходит автоматический набор с правками администратора. Окно подборки не меняется.
- **Оценки не редактируются.** Оценка модели показывается только для чтения; составом управляет переключатель.
- **Решение администратора снимает документ с ожидания.** Документы, по которым администратор принял решение, не оцениваются финальным проходом, не задерживают отправку и (если исключены) не получают повторную попытку саммари.
- **Подборка без саммари невозможна.** Акт без саммари нельзя включить, пока оно не появится (автоматически или вручную).
- `/test_digest weekly` учитывает правки администратора и остаётся локальным предпросмотром.
- Без `WEBAPP_URL` или без `ADMIN_CHAT_IDS` модерация недоступна, подборка работает как раньше (автоматически), в лог пишется предупреждение.

## Capabilities

### New Capabilities
- `weekly-digest-moderation`: служебное напоминание только администраторам, панель (вход по `initData` и магической ссылке, включение и исключение документов, саммари, экспорт в Markdown), правила применения решений администратора.

### Modified Capabilities
- `weekly-important-digest`: «Состав и порядок подборки» (решения администратора поверх автоматического выбора), «Саммари пунктов подборки» (повторная попытка только для уходящих документов), «Отложенная отправка» (документы с решением администратора не ждут оценки), «Админский предпросмотр» (учитывает решения администратора).

## Impact

- Код: новый `app/webapp/admin.py` (эндпоинты панели, вход, сессии) и статические `app/webapp/static/admin.html`, общий `webapp.css` (общие стили выносятся из `HTML_PAGE` в `server.py`); `app/webapp/server.py` (подключение роутов и общих стилей); новый `app/services/weekly_review.py` (итоговый выбор, целевой период, Markdown); `app/services/scheduler.py` (напоминание, итоговый выбор при отправке и предпросмотре, финальный проход с учётом решений); `app/bot/handlers.py` (`/admin`, кнопка «Ссылка для браузера»); `app/main.py` (регистрация команды, кнопки и задачи напоминания); `app/core/config.py` (`WEEKLY_REVIEW_TIME`); `app/core/database.py` (новая колонка).
- БД: новая колонка `articles.digest_override` (`include` / `exclude` / `NULL`), добавляется тем же способом (`PRAGMA table_info` + `ALTER TABLE … ADD COLUMN`), что `importance`; новая таблица `weekly_review_pings` (отметка отправленного напоминания), создаётся `create_all`. `weekly_digest_runs` не меняется.
- API: `GET /admin`, `GET /admin/login`, `GET/POST /admin/api/*` — доступны только администраторам; CORS для них не включается.
- Безопасность: токены ссылки одноразовые и короткоживущие, сессия в `HttpOnly`/`Secure`/`SameSite=Strict` cookie, токен не остаётся в URL после обмена (access-лог пишет query-строки).
- Зависимости: новых нет. Предусловие: change `weekly-important-digest` (уже влит).
- Вне объёма: согласование подборки и фиксация набора, ручная правка оценок, экспорт уже отправленной подборки, повторное напоминание, публикация в Telegram-канал ботом, MCP-сервер для Claude Desktop, переупорядочивание законов вручную, отписка пользователей от подборки, ограничение повторов оценки при невалидном ответе GigaChat (issue #11).
