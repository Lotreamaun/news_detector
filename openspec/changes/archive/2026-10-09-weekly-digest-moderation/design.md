## Context

См. proposal.md — Why и What Changes. Состояние кода, от которого отталкивается дизайн:

- Недельная подборка работает целиком в `app/services/scheduler.py`: `_load_weekly_window` (окно по `created_at`), `_select_weekly` (оценка ≥ 2), `_split_by_summary`, `_select_unrated`, `_build_weekly_message`, `_send_weekly_digest` под `asyncio.Lock` из `bot_data["weekly_digest_lock"]`, `build_weekly_preview` для `/test_digest weekly`. Финальный проход в `_send_weekly_digest` оценивает всех неоценённых кандидатов окна (`_rate_article(final=True)`, в том числе по названию), откладывает отправку, пока они остаются, и делает «попытку 2» саммари для важных без саммари.
- Идемпотентность хранится в `weekly_digest_runs` (`period_end` unique, `started_at` NOT NULL, `finished_at`): строка создаётся в момент начала отправки — после финального прохода и выбора набора.
- Новые колонки в существующие таблицы проект добавляет в `app/core/database.py` через `PRAGMA table_info` + `ALTER TABLE … ADD COLUMN` (так добавлены `importance`, `is_demo`, `created_at`).
- Mini-App (`app/webapp/server.py`): одна огромная строка `HTML_PAGE` со стилями внутри (аккордеон `.doc`, плашки `.sum`/`.error`/`.unavailable`, баннер `.toast`, кнопка `.sum-btn` с кулдауном, тёмная тема), проверка подписи `initData` (`_verify_init_data`), CORS `*` на существующих роутах, `POST /summarize` с серверным кулдауном (`app["summarize_failed_at"]`).
- Access-лог aiohttp пишет query-строки (в логах видно `GET /app?ids=…`), поэтому секреты в URL недопустимы.
- `ADMIN_CHAT_IDS` уже означает «админ» (`/test_digest`, безлимитные саммари). Гейт подписки на канал (`require_channel_verified`) исключений для админов не делает.
- `force_summarize` — путь «Сделать саммари» с лимитами пользователей (админы без лимита).
- В `_build_digest` тизер показывает до трёх законов целиком (заголовок + саммари), лимит сообщения Telegram — 4096 символов.

## Goals / Non-Goals

**Goals:**
- Администратор за несколько минут — с телефона или с компьютера — проверяет подборку, исправляет состав и саммари; ничего критичного не зависит от того, успел ли он.
- Служебные сообщения и панель структурно отделены от пользовательской рассылки: утечка администраторского сообщения подписчикам невозможна по построению, а не по аккуратности кода.
- Окно подборки и её регулярность не меняются; панель показывает ровно то, что уйдёт.
- Минимум нового: без зависимостей, сборки фронтенда, фоновых очередей, без новых состояний периода.

**Non-Goals:**
- Согласование подборки и фиксация набора до отправки (рассматривалось и отклонено: сдвиг окна по моменту согласования, инвариант «нет неоценённых», отзыв и блокировки не окупаются для одного администратора; при необходимости — отдельный change).
- Ручная правка оценок важности: составом управляет переключатель, оценка остаётся ответом модели.
- Экспорт уже отправленной подборки: пост в канал пишется до отправки по живому набору.
- Публикация в Telegram-канал ботом, MCP для Claude Desktop.
- Ручное упорядочивание законов, поиск и массовые операции по списку, история изменений.
- Многопользовательская модерация с блокировками: двое администраторов — «последний сохранил выиграл».
- Повторное напоминание; ограничение повторов оценки при невалидном ответе модели (issue #11).

## Decisions

1. **Три слоя вместо роста `scheduler.py`.**
   - `app/services/weekly_review.py` — правила модерации без HTTP и без импорта `scheduler` (чтобы не было цикла): итоговый выбор, целевой период, краткое название, Markdown. Функции принимают готовые списки статей.
   - `app/webapp/admin.py` — только HTTP: вход, сессии, роуты API, проверка роли, сериализация; оркестрирует `scheduler` (загрузка окна) и `weekly_review`.
   - `app/services/scheduler.py` — напоминание, итоговый выбор и финальный проход с учётом решений администратора.
   Альтернатива — всё в `scheduler.py`: файл уже ~850 строк. Альтернатива — класс «модератор»: проект сознательно без лишних абстракций, поэтому функции.

2. **Решение администратора — колонка документа, а не запись о периоде.** `articles.digest_override` (`'include'` / `'exclude'` / `NULL`), добавляется в `app/core/database.py` по образцу `importance`. Каждый документ принадлежит ровно одному окну, поэтому привязка к периоду не нужна. Переключатель всегда пишет явное значение (`include` или `exclude`); `NULL` значит «администратор не трогал». «Возврата в автоматическое состояние» нет: для неоценённого документа автоматическое состояние ещё не известно, и нормализация превратила бы «исключить» в «пусть решит модель». Альтернатива — таблица на период с JSON-списками: лишняя нормализация и ключи периода без выгоды.

3. **Итоговый выбор — одна функция.** `final_selection(window)`: документы окна с саммари, у которых `digest_override == 'include'` либо (`digest_override is None` и оценка ≥ 2). Порядок: ранг = оценка (без оценки — `-1`), по убыванию; внутри ранга — более поздняя дата публикации выше. Включённые документы с оценкой `1`, `0` и без оценки естественно оказываются после `3` и `2`. Эту функцию используют рассылка, панель, экспорт и `build_weekly_preview`, поэтому все четыре показывают одно и то же. Сохранённые решения применяются всегда, в том числе если модерация позже стала недоступна.

4. **Решение администратора окончательно для финального прохода.** В `_send_weekly_digest`:
   - финальная оценка и ожидание касаются только неоценённых документов с `digest_override is None`; документы с решением не оцениваются и не задерживают отправку;
   - «попытка 2» саммари — только для документов, которые реально пойдут: оценка ≥ 2 и не `exclude` (включённые администратором уже имеют саммари);
   - в последний час воскресенья исключаются только неоценённые без решения.
   Фоновая оценка в течение недели (`_rate_article`, `_rate_backlog`) не меняется: она дешёвая и держит `importance` заполненной.

5. **Какой период показывает панель.** Пусть `P` — последний наступивший запланированный момент. Если отправка за `P` не завершена (`finished_at` пуст) и не прошёл её жёсткий срок (воскресенье 22:00), целевой период — `P`, окно `(P − 7 дней, P]` (отправка отложена или идёт). Иначе целевой — следующий момент, окно `(P, сейчас]` (набор накапливается). Функция `target_period(now, runs)` в `weekly_review.py`. Отправленный период в панели не показывается.

6. **Правки после начала отправки отклоняются.** Изменяющие запросы проверяют `started_at` целевого периода: если он есть — ответ 409 с сообщением, панель перезагружает состояние. Общая блокировка с отправкой не нужна: набор выбирается до записи `started_at`, поэтому правка, сделанная во время финального прохода (до `started_at`), может не попасть в отправку — гонка в пределах минуты в пятницу 18:00, принята.

7. **Напоминание — отдельный путь отправки, не связанный с рассылкой.** `_send_review_ping` перебирает `config.ADMIN_CHAT_IDS` и вызывает `bot.send_message` напрямую; он не читает таблицу `users`, не использует `_notify_users_batch`/`_send_notification` (которые деактивируют пользователей по `Forbidden`) и не принимает список получателей извне. Текст начинается с пометки «🛠 Служебное сообщение для администратора». Кнопки: `web_app` на `/admin` и callback «🔗 Ссылка для браузера» (тот же код, что `/admin`). Ошибка отправки одному администратору логируется и не влияет на других. Идемпотентность — таблица `weekly_review_pings` (`period_end` unique, `pinged_at`), создаётся `create_all`: деплой в пятницу после 12:00 не присылает напоминание повторно. Вызывается пятничной задачей `weekly_review_job` в `WEEKLY_REVIEW_TIME`, концом каждого цикла проверки и после старта при условиях: сейчас ≥ время напоминания этой пятницы, < запланированный момент, период не отправлен, записи в `weekly_review_pings` нет. Альтернатива — отметка в `bot_data`: каждый пятничный деплой давал бы лишнее служебное сообщение.

8. **Конфигурация.** `WEEKLY_REVIEW_TIME` (по умолчанию `12:00`, пусто = без напоминания; формат и пояс как у `WEEKLY_DIGEST_TIME`; значение должно быть раньше `WEEKLY_DIGEST_TIME`, иначе `ConfigError`). Модерация доступна, когда заданы `WEEKLY_DIGEST_TIME`, `WEBAPP_URL` и непустой `ADMIN_CHAT_IDS`; иначе в лог при старте пишется причина, рассылка идёт автоматически.

9. **Вход.**
   - Mini-App: `initData` передаётся заголовком `X-Telegram-Init-Data`; роль проверяется по `ADMIN_CHAT_IDS`; используется `_verify_init_data` (срок 24 часа).
   - Браузер: `/admin` в боте и кнопка «Ссылка для браузера» (обе за гейтом подписки, как остальные команды и кнопки) вызывают `issue_login_token(telegram_id)` из `admin.py`: случайные 32 байта, одноразовый, TTL 10 минут, хранится в памяти процесса. `GET /admin/login?t=…` гасит токен, создаёт сессию (TTL 12 часов, в памяти), ставит cookie `admin_session` (`HttpOnly`, `SameSite=Strict`, `Secure` — только если `WEBAPP_URL` начинается с `https`, иначе браузер не примет cookie на локалхосте), отвечает 302 на `/admin`. Токен виден в access-логе единожды, но к этому моменту уже погашен. Ссылку в напоминание положить нельзя (TTL 10 минут), поэтому кнопка выдаёт свежую по нажатию.
   - Хранение сессий в памяти: перезапуск процесса (деплой) сбрасывает сессии, администратор снова выполняет `/admin`. Сценарий использования — раз в неделю, поэтому 12 часов достаточно. Альтернатива — таблица сессий: не оправдана для одного-двух администраторов.
   - Альтернатива Telegram Login Widget отвергнута: нужен `/setdomain` у BotFather и привязка домена, а ngrok-адрес меняется.
   - Браузерный режим нужен, потому что Mini-App в Telegram Desktop открывается маленьким окном, а пост в канал пишется на компьютере.

10. **Защита API.** Все `/admin/api/*` вызывают `require_admin(request)`: сначала заголовок `initData`, затем cookie. CORS не включается, `Access-Control-Allow-Origin` не отправляется. Изменяющие запросы (POST) требуют заголовок `X-Admin-Panel: 1` и `Content-Type: application/json`: кросс-сайтовая форма или `fetch` без CORS не смогут их выставить (preflight не пройдёт). `GET /admin` отдаёт статичную страницу без данных — открытие без входа показывает экран «войдите через `/admin`».

11. **Общие стили выносятся в `app/webapp/static/webapp.css`.** Блок `<style>` из `HTML_PAGE` переезжает в этот файл (раздаётся `add_static`), `HTML_PAGE` подключает его `<link>`; специфичное для панели лежит в `admin.html`. Первым шагом — с проверкой, что существующая страница выглядит как раньше. Альтернатива — скопировать правила в `admin.html`: быстрее, но две копии темы разъедутся. `app/webapp/static/` не исключён из образа (`.dockerignore`).

12. **Ручное саммари — обычное саммари.** Запись в `Article.summary` (обрезка пробелов, 1–600 символов). Предел 600 из соображения лимита Telegram: тизер показывает три закона целиком (3 × (заголовок до ~300 + саммари 600 + ссылка) с экранированием MarkdownV2 ≈ 3300 символов при лимите 4096). Генерация моделью использует `force_summarize` с администратором как пользователем (без лимита) и общий кулдаун `app["summarize_failed_at"]`.

13. **Markdown.** Для каждого документа итогового набора: строка `**Название**` (нормализованный заголовок как в рассылке), строка с саммари, строка `[Читать на портале](url)`; блоки разделены пустой строкой. Строит сервер (`GET /admin/api/export`) через `final_selection`, чтобы порядок и нормализация совпали с рассылкой. Дополнительного экранирования Markdown нет: текст предназначен для чтения человеком и Claude. Копирование — `navigator.clipboard`, при отказе (WebView) — запасное поле с выделением текста. Если после экспорта появился новый документ, расхождение видно по счётчику «Уйдёт N законов»; отдельной отметки нет.

14. **UX панели.**
    - **Главный сценарий** — за 1–3 минуты: посмотреть список, поправить 1–2 спорных пункта, при необходимости скопировать Markdown. Сводка закреплена вверху, внизу (`position: sticky`) — итоговая строка «Уйдёт N законов · пт 18:00 (через 3 ч 12 мин)» и кнопка «Скопировать Markdown». Нативную `MainButton` Telegram не используем: поведение должно быть одинаковым в Mini-App и браузере.
    - **Иерархия экрана:** сводка → «В подборке» → «Ещё не оценены» (только при наличии, с пояснением «оценит модель перед отправкой») → «Не вошли» (свёрнут).
    - **Карточка:** в свёрнутом виде — переключатель, краткое название, чип оценки (только просмотр), первые строки саммари; в раскрытом — полное название, редактор саммари, ссылка на портал и ссылка на полный текст. Переключатель стоит у правого края отдельной областью нажатия ≥ 44 px, не конфликтует с раскрытием карточки. Бинарное состояние «в подборке / нет» — переключатель, а не флажок: действие мгновенное и обратимое.
    - **Краткое название:** «Федеральный закон № 282-ФЗ · О цифровых валютах и цифровых правах» вместо «Федеральный закон от 04.08.2026 № 282-ФЗ "О цифровых…"»; разбор по шаблону с запасным вариантом — полное название.
    - **Чип оценки:** фиксированные цвета и подпись (3 · критично, 2 · важно, 1 · нейтрально, 0, «не оценён»), цвет не единственный носитель смысла; нажатием не меняется.
    - **Без саммари:** переключатель отключён и подписан «нужно саммари»; в карточке две кнопки — «Сделать через GigaChat» и «Написать вручную». Кнопка модели после неудачи приглушена на 60 секунд, как в Mini-App.
    - **Редактор саммари:** поле с живым счётчиком «n/600», явные «Сохранить»/«Отмена», пометка «изменено», предупреждение при уходе со страницы или сворачивании несохранённой карточки. Сохранение переключателя, наоборот, мгновенное с оптимистичным откатом.
    - **Обратная связь:** «Сохранено ✓» в шапке (гаснет через пару секунд), баннер ошибки тем же стилем `.toast`, что в Mini-App; спиннер на кнопках модели.
    - **Идёт отправка:** если у целевого периода есть `started_at`, панель показывает «Идёт отправка» и становится только для просмотра до перехода к следующему периоду.
    - **Свежесть данных:** автообновление раз в минуту, пока вкладка видима, и при возвращении фокуса; новые документы подсвечиваются меткой «новое» (сравнение со списком предыдущей загрузки на клиенте). Параллельные правки двух администраторов разрешаются обновлением состояния.
    - **Доступность:** подписи `aria-label` у переключателей, роли у разделов, управление с клавиатуры (Пробел — переключить, Enter — раскрыть), `prefers-reduced-motion`.
    - **Не делаем (YAGNI):** сортировка перетаскиванием, поиск, массовое выделение, отмена последнего действия, история.

15. **Совместимость с предпросмотром.** `build_weekly_preview` переходит на `final_selection`, поэтому `/test_digest weekly` показывает ровно то, что получится с учётом решений администратора, и дополнительно перечисляет включённые и исключённые администратором документы.

## Risks / Trade-offs

- [Панель с правом записи доступна из интернета (туннель, Dockhost)] → вход только администраторам, подпись `initData` либо одноразовая ссылка + cookie `HttpOnly`/`SameSite=Strict`, CORS выключен, обязательный заголовок для POST; токен гасится при первом открытии.
- [Перезапуск процесса сбрасывает сессии и невыданные токены] → администратор выполняет `/admin` заново; сообщение об истёкшей сессии содержит подсказку.
- [Документ с оценкой ≥ 2, пришедший после просмотра панели, уходит без проверки] → принято: регулярность важнее; администратор может открыть панель ещё раз до 18:00, автообновление и метка «новое» показывают свежие документы.
- [Пост в канал разойдётся с подборкой, если документ пришёл после экспорта] → видно по счётчику «Уйдёт N законов»; повторный экспорт или исключение документа.
- [Администратор не открыл панель] → рассылка уходит как без модерации, с правками, если они были; напоминание — единственная нагрузка на его внимание.
- [Правка во время финального прохода в 18:00 не попадает в отправку] → гонка в пределах минуты, принята; после записи `started_at` правки отклоняются явно.
- [Исключённый неоценённый документ так и останется неоценённым до фоновой оценки] → его оценка ни на что не влияет; фоновая оценка продолжает работать.
- [Ручное саммари с ошибкой или спорным содержанием уходит подписчикам] → ответственность администратора; предел 600 символов и обязательное явное сохранение.
- [Вынос стилей меняет рабочую страницу Mini-App] → отдельная первая задача и ручная проверка в светлой и тёмной темах до остальной работы.
- [Cookie `Secure` не ставится на `http`] → в разработке на `http://localhost` ставится без `Secure`; в проде `WEBAPP_URL` обязан быть `https` (Telegram требует его для Mini-App).
- [Две вкладки или два администратора правят одновременно] → последний сохранивший побеждает; автообновление снижает расхождение.
