## Purpose

Гарантирует, что бот забирает с портала публикаций все документы периода, а не только первую страницу ответа API, и не теряет документы при частичных сбоях загрузки.

## ADDED Requirements

### Requirement: Загрузка всех страниц ответа API
При каждой проверке портала публикаций система SHALL получать документы со всех страниц ответа API (до общего числа страниц, которое сообщает API), а не только с первой. Это SHALL относиться и к регулярной проверке, и к однодневной загрузке бэкфилла.

#### Scenario: Документы на нескольких страницах
- **WHEN** за период проверки API сообщает 222 документа на 8 страницах
- **THEN** система обрабатывает все 222 документа, а не только документы первой страницы

#### Scenario: Документы умещаются на одной странице
- **WHEN** API сообщает одну страницу
- **THEN** система делает один запрос и обрабатывает все её документы

#### Scenario: Пачка новых актов больше размера страницы
- **WHEN** за один цикл проверки появилось больше документов, чем помещается на первую страницу (например, 59 ФЗ за день)
- **THEN** каждый из них сохраняется и проходит обычную обработку и рассылку

### Requirement: Устойчивость к сбою отдельной страницы
Если загрузка одной из страниц не удалась после всех повторных попыток, система SHALL сохранить и обработать документы, полученные с остальных страниц, записать предупреждение в лог и не прерывать цикл проверки. Если не удалась первая страница, система SHALL вести себя как при недоступности API (цикл пропускается без падения).

#### Scenario: Сбой второй страницы
- **WHEN** из 3 страниц ответа не загрузилась вторая
- **THEN** документы первой и третьей страниц обрабатываются, в лог пишется предупреждение, а документы второй страницы подхватываются следующим циклом, пока они остаются в окне API

#### Scenario: Недоступна первая страница
- **WHEN** первая страница не загрузилась после всех повторных попыток
- **THEN** цикл проверки пропускается без исключения, пользователям ничего не рассылается, следующий цикл запускается по расписанию

### Requirement: Защита от бесконечной пагинации
Система SHALL ограничивать число загружаемых за один запрос периода страниц фиксированным потолком, чтобы некорректный ответ API (неверное число страниц) не приводил к бесконечному или чрезмерному числу запросов.

#### Scenario: API сообщает аномально большое число страниц
- **WHEN** API возвращает число страниц выше потолка
- **THEN** система загружает страницы только до потолка и пишет предупреждение в лог

### Requirement: Набор принимаемых типов не сужается
Регулярная проверка SHALL по-прежнему принимать документы всех видов актов (включая региональные и ведомственные), чтобы фильтры пользователей по уровням силы (`/settings`) продолжали работать. Загрузка бэкфилла SHALL по-прежнему ограничиваться на стороне API видами «ФЗ» и «ФКЗ» за окно в 30 дней.

#### Scenario: Региональный акт принимается
- **WHEN** на портале опубликован региональный акт, а у пользователя в фильтре выбран уровень `REGIONAL`
- **THEN** акт попадает в приём и рассылается этому пользователю, как и до изменения

#### Scenario: Бэкфилл по-прежнему только ФЗ и ФКЗ
- **WHEN** выполняется бэкфилл за 30 дней
- **THEN** в БД загружаются только документы видов «ФЗ» и «ФКЗ», окно и условие запуска бэкфилла не изменились
