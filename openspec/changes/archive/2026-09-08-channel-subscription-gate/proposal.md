## Why

Продукт ещё не запущен (сейчас 2 пользователя — автор и тестовый инженер), и это последний момент, когда можно ввести обязательную подписку на Telegram-канал без миграции существующей аудитории. Ручное тестирование выявило, что новый пользователь начинает получать регулярные уведомления сразу после `/start`, не будучи ничем связан с продуктом (не подписан на канал), что не даёт возможности удерживать аудиторию через канал как основной канал коммуникации.

## What Changes

- Новое поле `User.channel_verified` (bool), по умолчанию `True` на уровне БД (`server_default`) — сохраняет текущее поведение для уже существующих строк без миграции данных.
- Регистрация нового пользователя (`/start` для ранее не существовавшего `telegram_id`) явно выставляет `channel_verified = False`.
- Новая переменная окружения для идентификатора требуемого канала (заглушка в `.env.example`, значение заполняется отдельно, не в рамках этого change).
- Новая функция проверки подписки через Telegram Bot API `get_chat_member` — оформлена как переиспользуемый сервис (не привязана жёстко к одному обработчику), чтобы её можно было позже вызывать не только на онбординге.
- Новый callback-обработчик "Проверить подписку": при успешной проверке выставляет `channel_verified = True`.
- `scheduler._notify_users` дополнительно исключает пользователей с `channel_verified = False` из рассылки регулярных уведомлений.
- Проверка подписки выполняется один раз (на онбординге), не перед каждой рассылкой — периодическая перепроверка не входит в этот change.

## Capabilities

### New Capabilities
- `channel-subscription-gate`: механика проверки подписки пользователя на обязательный Telegram-канал (поле `channel_verified`, конфигурация канала, сервис проверки через `get_chat_member`, обработчик подтверждения) и её влияние на право пользователя получать регулярные уведомления.

### Modified Capabilities
- `law-force-filter`: требование «Фильтрация уведомлений» (`scheduler._notify_users`) дополняется условием — уведомление отправляется, только если у пользователя одновременно подходит уровень статьи под фильтр И `channel_verified = True`.

## Impact

- `app/models/user.py` — новое поле `channel_verified`.
- `app/core/config.py`, `.env.example` — новая переменная канала (заглушка).
- `app/services/` — новый сервис проверки подписки (`get_chat_member`).
- `app/bot/handlers.py` — новый callback "Проверить подписку", изменение регистрации нового пользователя в `/start` (выставление `channel_verified = False`).
- `app/services/scheduler.py` — `_notify_users` учитывает `channel_verified` при выборке получателей.
- Существующие 2 пользователя не затрагиваются (сохраняют `channel_verified = True` по умолчанию БД).
- Точная перестройка `/start` UI (порядок экранов, кнопка "Как это работает?") — предмет отдельного change `onboarding-flow-redesign`, зависящего от этого.
