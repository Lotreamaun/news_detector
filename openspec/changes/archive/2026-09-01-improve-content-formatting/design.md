## Context

Сейчас текст доходит до пользователя в трёх местах: `/latest` (handlers.py: разметка MarkdownV2 через `escape_markdown`), `/summary`/кнопка «Сделать саммари» (общая `_summarize_and_reply` → `_deliver`, текст `{title}\n\n{summary}\n\n{url}` без разметки), уведомления (`_build_notification` в scheduler.py). Источник текста: `get_legal_text` (HTML редакции → `_html_to_text`, который уже режет HTML, но `<br>`/блочные теги дают лишние переводы строк) и OCR через GigaChat (в распознанный текст могут попадать сырые фрагменты разметки), а также саммари, сгенерированное LLM. Мотивация — см. proposal.md (Why); требования — specs/content-formatting/spec.md.

## Goals / Non-Goals

**Goals:**
- Единый механизм нормализации сырого текста (убрать `<br />`, теги, лишние пробелы/пустые строки) перед отправкой в Telegram — включая заголовки/названия документов (фикс `<br />` в title).
- Аккуратная MarkdownV2-разметка **во всех сообщениях по умолчанию** (`/latest`, `/summary`/кнопка, уведомления/`/notify_me`) с корректным экранированием (фикс: раньше красиво было только после принудительной саммаризации).
- Ссылка на оригинал на правовом портале присутствует **всегда**; дисклеймер в сообщениях не показывается (перенесён в WebApp).
- Переиспользовать существующую доставку (`_deliver`/`_build_notification`), не дублировать.

**Non-Goals:**
- Instant View не используется (отказ от идеи: нет утверждённого шаблона под `publication.pravo.gov.ru`). Также вне скоупа — **Telegram WebApp/Mini-App** для просмотра полного текста (отдельная фича, требует HTTPS-хостинга и развёртывания; текст по-прежнему доступен по ссылке на оригинал).
- Не вводим новую схему хранения текста (используем существующие поля) — пере-разметка на лету при отправке.
- Лендинг — вне скоупа.

## Decisions

### 1. Нормализация текста — единый хелпер `_normalize_text(text) -> str` + чистка заголовка при сохранении

Централизуем чистку в один хелпер (в `app/services/rss_parser.py` рядом с `_html_to_text`, чтобы было близко к источнику):
- удаляем HTML-теги и сущности `&...;`, включая явные `<br>`, `<br/>`, `<br />`;
- схлопываем множественные пробелы/`\t`/неразрывные пробелы;
- убираем избыточные пустые строки (оставляем не более одной).
Применяется к результату `_html_to_text`, к распознанному OCR-тексту, к саммари и к заголовку. Дополнительно: в `_entry_from_item` заголовок `title` нормализуется через `_normalize_text` уже при записи `Article` в БД (фикс: «Постановление …№ 111<br /> „Об утверждении…“» больше не попадает в БД с тегом). В `_format_summary` title также нормализуется перед `escape_markdown`.

Почему частично на лету, частично при сохранении: формат вывода может меняться, но заголовок с `<br />` — дефект входных данных, его выгодно чистить сразу при сохранении, чтобы не чинить отображение в каждом месте. Уже сохранённые записи правятся на лету при сборке сообщения.

### 2. MarkdownV2-разметка — применяется по умолчанию во всех сообщениях

Вводим `_format_summary(summary, title) -> str` (в handlers.py) без дисклеймера, который возвращает:
- жирный заголовок `*title*` (title предварительно нормализован через `_normalize_text`);
- саммари с выделением ключевых пунктов, экранированное `escape_markdown(..., version=2)`;
- разделители и ссылку на оригинал через `_full_text_block`.
Всё — с `parse_mode="MarkdownV2"`. Применяется по умолчанию во всех точках: `/latest`, `/summary`/кнопка (`_deliver`/`_summarize_and_reply`), уведомления (`_build_notification`/`_notify_users`) и `/notify_me` — раньше уведомления были plain text, теперь собираются тем же форматированием и отправляются с `parse_mode="MarkdownV2"`. Экранирование строго через `telegram.helpers.escape_markdown`, чтобы разметка не ломалась.

### 3. Доступ к полному тексту — ссылка на оригинал всегда

Полный текст закона распознаётся при OCR/саммаризации и сохраняется в `original_text`, но показ полного текста в Telegram не входит в скоуп (WebApp-просмотр — отдельная фича). Пользователю гарантированно отдаётся ссылка на оригинал на `publication.pravo.gov.ru` (`_full_text_block` в handlers.py) — она присутствует во всех сообщениях с законом (`/latest`, `/summary`, уведомления) и ничем не заменяется.

### 4. Дисклеймер вынесен из сообщений в WebApp

Дисклеймер «⚠️ *Текст распознан ИИ, возможны ошибки*» в сообщениях бота (саммари, уведомления) не показывается — для саммари он излишен. Дисклеймер живёт только внутри WebApp (`law-text-webapp`) вверху перед текстом закона. Из `_format_summary` (параметр `with_disclaimer`) и из `_build_notification` (`_AI_DISCLAIMER`/`_AI_DISCLAIMER_TEXT`) дисклеймер удаляется.

### 5. Места применения

- `/latest` (handlers.py) — формат через `_format_summary` + ссылка на оригинал (MarkdownV2 по умолчанию, title нормализован).
- `/summary`/кнопка (`_summarize_and_reply` → `_deliver`) — формат саммари + ссылка на оригинал (MarkdownV2, без дисклеймера).
- уведомления (`_build_notification`/`_notify_users`) и `/notify_me` — тот же MarkdownV2-формат по умолчанию + ссылка на оригинал (без дисклеймера). Починка `notify_me`: убрать leftover `context.bot_data["config"].WEBAPP_URL`, вызывать `_build_notification(article)` с `parse_mode="MarkdownV2"`.

## Risks / Trade-offs

- [Непроэкранированный Markdown ломает сообщение] → всё экранируем `escape_markdown(version=2)`, единый хелпер, проверяем отправку на тесте.
- [Чистка на лету может исказить структуру длинного текста] → нормализация консервативна (только артефакты/пробелы), разбивку по абзацам сохраняем.
- [OCR-текст может быть большим для одного сообщения] → при превышении лимита Telegram отдаём только саммари + ссылку на оригинал (полный текст вне сообщения).

## Migration Plan

- Никаких миграций БД по схеме (заголовки чистятся на лету; новые title уже пишутся нормализованными).
- Вкатывается пошагово: (1) нормализация заголовков → (2) Markdown-формат во всех сообщениях по умолчанию → (3) убрать дисклеймер из сообщений. Роллбэк — вернуть способ показа саммари. Дисклеймер остаётся в WebApp (`law-text-webapp`).

## Open Questions

- Точный источник `<br />` в конкретных документах (OCR vs HTML-редакция) — не влияет на подход, уточняется при отладке.
- Полнотекстовый просмотр в Telegram (Telegram WebApp) вынесен в отдельную фичу — см. Non-Goals.
