## Purpose

Гарантирует, что логи бота (консоль и файл) не раскрывают токен Telegram-бота, даже при
уровне логирования INFO или DEBUG, заданном через `LOG_LEVEL`.

## ADDED Requirements

### Requirement: Логи не содержат токен Telegram-бота
Система SHALL NOT записывать значение `TELEGRAM_BOT_TOKEN` ни в консольный вывод, ни в
файл логов при штатной работе бота (polling, отправка сообщений, обработка команд),
независимо от значения `LOG_LEVEL`.

#### Scenario: Штатный polling на уровне INFO
- **WHEN** бот запущен с `LOG_LEVEL=INFO` и выполняет несколько циклов получения обновлений от Telegram
- **THEN** ни одна строка в консоли и в файле логов не содержит значение `TELEGRAM_BOT_TOKEN`

#### Scenario: Отправка уведомлений пользователям
- **WHEN** бот рассылает уведомление о новом законе подписчикам при `LOG_LEVEL=INFO`
- **THEN** ни одна строка в логах не содержит значение `TELEGRAM_BOT_TOKEN`

#### Scenario: Отладочный уровень логирования
- **WHEN** бот запущен с `LOG_LEVEL=DEBUG`
- **THEN** построчные логи HTTP-запросов HTTP-клиента Telegram (URL запроса) не выводятся, и значение `TELEGRAM_BOT_TOKEN` в логах не появляется

#### Scenario: Служебные отладочные логи Telegram-библиотеки
- **WHEN** бот запущен с `LOG_LEVEL=DEBUG` и Telegram-библиотека при инициализации логирует адрес Bot API
- **THEN** вместо значения `TELEGRAM_BOT_TOKEN` в строке лога стоит маска, остальной текст сообщения сохраняется

#### Scenario: Токен в тексте исключения
- **WHEN** в лог пишется исключение, в сообщении или трейсбеке которого есть значение `TELEGRAM_BOT_TOKEN`
- **THEN** в консоли и в файле логов токен заменён маской

### Requirement: Ошибки HTTP-клиента остаются видимыми
Система SHALL продолжать логировать предупреждения и ошибки HTTP-клиента, через который
бот общается с Telegram, чтобы сетевые сбои оставались диагностируемыми.

#### Scenario: Сетевая ошибка при обращении к Telegram
- **WHEN** HTTP-клиент Telegram сообщает о проблеме на уровне WARNING или выше
- **THEN** это сообщение попадает в логи
