## Why

В прод-логах (Dockhost, `logs/app.log`) каждые несколько секунд пишутся строки вида
`INFO httpx: HTTP Request: POST https://api.telegram.org/bot<TOKEN>/getUpdates "HTTP/1.1 200 OK"`
— то есть полный токен Telegram-бота. PTB ходит в Bot API через `httpx`, а Telegram
требует передавать токен прямо в пути URL. `_configure_logging()` в `app/main.py` ставит
root-логгер на `LOG_LEVEL` (INFO), и логгер `httpx` наследует этот уровень, потому что
нигде отдельно не поднят. Любой, у кого есть доступ к логам, получает полный контроль над
ботом. Токен уже утёк — фикс нужен срочно, до следующего релиза фич.

Кроме того, на `LOG_LEVEL=DEBUG` сама PTB (`telegram.ext.ExtBot`) при сборке бота пишет
`Set Bot API URL: https://api.telegram.org/bot<TOKEN>` и `Set Bot API File URL: …` —
поэтому одного понижения уровня `httpx` недостаточно.

## What Changes

- Поднять уровень логгеров `httpx` и `httpcore` до `WARNING` в `_configure_logging()`,
  независимо от `LOG_LEVEL`: строки «HTTP Request: … /bot<TOKEN>/…» перестают попадать и в
  консоль, и в файл.
- Форматтер логов в `_configure_logging()` заменяет точное значение `TELEGRAM_BOT_TOKEN`
  на `***` в итоговой строке (включая трейсбеки) для консоли и файла. Закрывает любой
  источник, а не только `httpx`.
- Ротация токена — **вне скоупа этого change**: сейчас прод работает на тестовом боте,
  токен сменится вместе со всем окружением при переезде на боевого бота. Фикс нужен до
  переезда, чтобы токен нового бота не попал в логи.
- Выкатить фикс в прод сразу (hotfix-ветка → PR → merge в `main` → автодеплой Dockhost).

## Capabilities

### New Capabilities
- `secret-safe-logging`: логи приложения (консоль и файл) не содержат токен Telegram-бота;
  шумное построчное логирование HTTP-запросов сторонних клиентов подавлено.

## Impact

- Код: `app/main.py` — `_configure_logging()` + небольшой класс-форматтер (~10 строк).
- Логи: исчезают INFO-строки `httpx`/`httpcore` (в т.ч. полезный-для-отладки, но опасный
  лог каждого `getUpdates`). Предупреждения и ошибки этих библиотек остаются. Там, где
  токен всё же встречается в тексте лога, он заменён на `***`.
- Инфраструктура: старые логи с токеном тестового бота остаются в истории Dockhost и в
  ротируемых `app.log.*`; токен выводится из употребления при переезде на боевого бота.
- Зависимости, БД, API бота — без изменений.
