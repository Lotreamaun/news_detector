## Context

Мотивация — см. proposal.md. Требования — `specs/today-digest/spec.md`.

Текущее состояние, которое определяет подход:

- `Article.published_at` — дата опубликования из API (`publishDateShort`, московская дата без времени). `_parse_api_datetime` сохраняет её как полночь с пометкой UTC: публикация 09.10 по Москве лежит в БД как `2026-10-09T00:00:00+00:00`. Значит, «акты за дату D» — это `published_at ∈ [D 00:00 UTC, D+1 00:00 UTC)`, где D — дата по Москве.
- Объём: ~500 актов в будний день, из них ≈95% региональные; федеральных 10–25; саммари есть у ~1%.
- `Article.level` для группировки «федеральное/региональное» не годится: распоряжения Правительства РФ и приказы федеральных служб получают `UNKNOWN`, региональные законы тоже `UNKNOWN`, часть региональных указов/постановлений (Якутия, Татарстан, ЯНАО) — `DECREE`/`GOV_RESOLUTION`. Править классификатор нельзя: от `level` зависят фильтры пользователей.
- `external_id` = `eoNumber` портала: `RR BB YYYYMMDD NNNN`, `RR` — код субъекта (`00` — федеральный уровень), `BB` — блок (`00` высшие органы, `01` исполнительные, `03` суды). Проверено на всех 488 актах за 08.10.2026 и на всей локальной БД; формат не задокументирован.
- Mini-App-дайджест (`/app?ids=`) создаёт карточки и сразу запрашивает `/full_text` по каждому id (полный текст в ответе), id в URL ограничены `DIGEST_ID_CAP = 30`. Для 500 актов не подходит ни по URL, ни по нагрузке.
- Аналог модуля чистых правил уже есть — `app/services/weekly_review.py` (без HTTP/БД/Telegram).

## Goals / Non-Goals

**Goals:**
- Одна чистая функция группы по `external_id`, общая для бота и Mini-App.
- Ни миграций, ни новых переменных `.env`, классификатор `level` и фильтры не трогаем.
- Страница дня: один лёгкий запрос списка при открытии, тексты — только по раскрытию.

**Non-Goals:**
- Названия регионов, подзаголовки и выбор региона в Mini-App — это issue #8 (справочник кодов портала).
- Поиск по тексту/саммари и по коду региона — только по заголовку.
- Кэширование ответа `/today_list`, пагинация, просмотр актов прошлых дней.
- Переходный ответ на `/latest`.

## Decisions

### 1. Группа — по префиксу `external_id`, а не по `level` или заголовку
`today.scope_of(external_id) -> "federal" | "regional" | "other"`: строка из 16 цифр → `"federal"` при префиксе `00`, иначе `"regional"`; всё остальное → `"other"`.
- *Альтернатива: `level`* — неверные группы (см. Context): около 30 федеральных актов в день попали бы в «Прочие».
- *Альтернатива: эвристика по заголовку* — промахи («Комитет по транспорту» СПб, «Кузбасс», «Югра»), регулярки, которые нужно поддерживать.
- *Альтернатива: поле API* — отдельного поля региона нет; `signatoryAuthorityId` — GUID без справочника.

### 2. Модуль чистых правил `app/services/today.py`
По образцу `weekly_review.py`: без Telegram, HTTP и сессий БД.
- `PORTAL_TZ = ZoneInfo("Europe/Moscow")` — константа, а не `WEEKLY_DIGEST_TZ`: это часовой пояс портала, а не настройка рассылки.
- `portal_today(now=None) -> date` и `day_bounds(d) -> (start, end)` — границы `[D 00:00 UTC, D+1 00:00 UTC)` под формат хранения `published_at`.
- `scope_of(external_id)` (решение 1).
- `importance_key(article)` — общий порядок важности: (ранг группы, ранг уровня для федеральных: `IMPORTANT_LEVELS` → `DECREE` → `GOV_RESOLUTION` → `DEPARTMENTAL` → прочее; `-importance` с NULL после оценённых; для региональных — блок `BB`; затем `external_id`).
- `pick_top(articles, n=3)` — первые n по `importance_key` (для тизера).
- `group_for_page(articles)` — группы в порядке «Федеральные, Региональные, Прочие»: федеральные по `importance_key`, региональные и прочие по `external_id`, пустая «Прочие» опускается.

Почему у региональных два порядка: в тизере важнее «высшие органы раньше ведомств» по всем регионам (блок первым), а в длинном списке Mini-App — «акты одного региона рядом» (код субъекта первым). На практике региональные попадают в тизер только в дни, когда федеральных меньше трёх.

### 3. Тизер собирается отдельной функцией в `handlers.py`, а не через `_build_digest`
`_build_digest` завязан на дневной дайджест: свой заголовок, свой `_digest_sort_key` (ставит ФЗ в конец — `_REST_LEVEL_ORDER` не знает важных уровней), кнопка с `ids=` и потолком. У `/today` нужны строка счётчиков групп, другой порядок и кнопка по дате. Параметризовать `_build_digest` ещё тремя флагами ради одного вызова сложнее, чем написать рядом `_build_today_message(articles, day, webapp_url)` на 30–40 строк. Блок акта (заголовок, саммари, «Читать на портале») оформляется так же, как в `_build_digest`, через `escape_markdown` и `_normalize_text`.

### 4. Запрос без тяжёлых колонок
И `/today`, и `/today_list` выбирают только нужные колонки (`external_id`, `title`, `summary`, `url`, `level`, `importance`) — `original_text` 500 актов в память не грузится. Фильтр: `published_at` в границах дня, `is_demo IS FALSE`. Сравнение по диапазону, а не `date(published_at)`: так же устроены существующие запросы, и это не зависит от строкового представления дат в SQLite.

### 5. Mini-App: режим `today` + эндпоинт `GET /today_list`, дата — только на сервере
- Кнопка тизера: `{WEBAPP_URL}/app?view=today` — без даты. Дату вычисляет `/today_list` в момент запроса (`portal_today()`); параметров эндпоинт не принимает, лишние игнорирует. Так страница показывает только сегодняшние акты, и подменить день в URL нельзя.
- *Альтернатива: дата в URL (`/app?date=…`)* — кнопка открывала бы «свой» день тизера, но любой мог бы вписать в адрес другую дату; по решению пользователя Mini-App показывает только сегодняшний день. Цена: кнопка из вчерашнего тизера откроет сегодняшний список — поэтому сверху надпись-пояснение с датой из ответа сервера («Законы, опубликованные на портале сегодня, 9 октября. Список пополняется в течение дня»).
- `/today_list` отвечает JSON `{date, total, groups: [{key, title, items: [{external_id, title, summary}]}]}` (порядок — решение 2), `date` — ISO-дата по Москве, страница форматирует её по-русски («9 октября»). Заголовок нормализуется на сервере (`_normalize_text`). `summary` включён: их мало, и превью саммари в заголовке карточки видно без загрузки текста. Пустой день → `total: 0, groups: []`, страница показывает «Сегодня пока ничего не опубликовано» без групп и поиска.
- Объём ответа — ~500 заголовков ≈ 100–150 КБ. Приемлемо для одного запроса, без пагинации.
- Страница: группы — `<details>` верхнего уровня со счётчиком (федеральные `open`), внутри — те же карточки `.doc`, что в режиме `ids`. Отличие одно: карточка создаётся из данных списка, а `fetchFullText` + `renderCard` вызываются на первом `toggle` → open (флаг `_loaded`). Кнопка «Сделать саммари», кулдаун и тосты переиспользуются без изменений.
- *Альтернатива: поднять `DIGEST_ID_CAP` / передавать ids* — URL кнопки растёт до десятков КБ, и остаётся 500 запросов полного текста при открытии.

### 6. Поиск — на клиенте по уже загруженным заголовкам
Поле над группами; на `input`: `norm(s) = s.toLowerCase().replace(/ё/g, 'е')`, у каждой карточки `hidden = !norm(title).includes(q)`; у группы — `hidden`, если совпадений нет, иначе `open` и счётчик «N из M»; если пусто везде — «Ничего не найдено». Пустой запрос восстанавливает исходное состояние (федеральные раскрыты, региональные свёрнуты). Нормализованный заголовок считается один раз при построении. Без debounce: 500 сравнений строк на нажатие — незаметно.

### 7. Удаление `/latest`
Обработчик, импорт и регистрация в `main.py`, `BotCommand`, строки в `HELP_TEXT` и приветствии `/start` заменяются на `/today`. В фолбэках кнопки примера («Попробуйте позже: /latest», «Попробуйте /latest») отсылка убирается, а не заменяется на `/today`: в пустой день `/today` тоже ничего не покажет. Хелперы `_window_start`, `_format_summary`, `_full_text_block` остаются — их используют пример уведомления и `/summary`. Меню команд Telegram перерегистрируется при старте (`_register_commands`).

## Risks / Trade-offs

- [Формат `eoNumber` не задокументирован, портал может его поменять] → нестандартные номера уходят в «Прочие» (группа видна, акты не теряются); логика в одной функции `scope_of`.
- [Конституционный Суд помечается `CONSTITUTION` (известная особенность `classify_level_for_title`) и попадёт в начало тизера] → принимаем: это всё равно федеральный акт; исправление классификатора — вне этого change.
- [Утром свежие акты ещё не оценены, `importance` NULL] → при равном уровне они идут после оценённых, затем по номеру; порядок уточняется в течение дня.
- [Счётчики в тизере расходятся со страницей, открытой позже; вчерашний тизер открывает сегодняшний список] → поведение описано в спеке как ожидаемое; дата в надписи-пояснении сверху страницы снимает путаницу.
- [Сразу после полуночи по Москве страница пуста, даже если тизер прислан минуту назад] → редкий случай; страница честно показывает «Сегодня пока ничего не опубликовано» с новой датой.
- [Регионы упорядочены по коду, а не по названию] → поиск по заголовку закрывает навигацию; названия появятся с #8.
- [500 `<details>` в DOM на слабом телефоне] → в DOM только заголовки, тексты подгружаются по раскрытию; региональная группа свёрнута по умолчанию.
- [`/today_list` без авторизации] → отдаёт только заголовки за сегодня — публичные данные портала; так же открыт `/full_text`.
- [У ~99% актов дня нет текста в БД (`original_text` есть у 2 из 488 за 08.10): при приёме редакция ещё не готова] → карточка на странице дня покажет фолбэк со ссылкой; текст по требованию дотягивает только «Сделать саммари» (тратит лимит пользователя и квоту GigaChat). Принимаем, `/full_text` не меняем.
- [По воскресеньям портал не публикует акты — `/today` весь день отвечает «Сегодня пока ничего не опубликовано»] → принимаем: отката на прошлый день нет, это следует из решения «только сегодня».
- [Распоряжения Правительства РФ получают `UNKNOWN` и ранжируются ниже ведомственных приказов] → принимаем: их заголовки без предмета («… № 2813-р»), в тизере они хуже понятного приказа; `level` и порядок не трогаем.

## Migration Plan

Обычный деплой контейнера: миграций и новых переменных нет. После старта бот перерегистрирует меню команд — `/latest` из него исчезнет, `/today` появится. Откат — revert коммита и повторный деплой; данные не затрагиваются.
