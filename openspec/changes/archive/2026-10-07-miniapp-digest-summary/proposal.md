## Why

WebApp-дайджест (кнопка «📖 Дайджест») сейчас показывает только свёрнутые заголовки и, при разворачивании, распознанный текст — саммари, даже если оно уже есть в БД, на странице не видно. Чтобы понять суть закона, пользователь должен либо читать весь текст, либо вернуться в чат и жать «Сделать саммари №N» (а эта кнопка есть только у первых 3 документов тизера). Хочется, чтобы суть была видна прямо в карточке, а недостающее саммари можно было заказать, не выходя из Mini-App.

## What Changes

- В каждой карточке (секции-аккордеоне) WebApp-дайджеста показывается саммари закона, если оно уже есть:
  - в свёрнутом состоянии — под однострочным заголовком, полностью (без обрезки);
  - в развёрнутом — после строки «Дата подписания» (или сразу после полного заголовка, если даты нет), перед текстом закона.
  - Оформление — плашка в акцентном цвете темы Telegram (цвет кнопки «Сделать саммари»), читаемая в светлой и тёмной теме и подписанная как саммари (метка «Саммари»).
- Карточка без саммари в свёрнутом виде выглядит ровно как сейчас; в развёрнутом виде — как сейчас плюс кнопка «Сделать саммари» на месте будущего саммари (после даты подписания). При разворачивании такой карточки страница один раз перепроверяет документ: если саммари уже появилось (например, его сделал другой пользователь, пока страница была открыта), карточка показывает его вместо кнопки.
- Нажатие «Сделать саммари» в карточке запускает ту же принудительную саммаризацию, что и кнопка в боте (месячный лимит, обход лимита для ФКЗ/ФЗ/Конституции и админов, OCR при отсутствии текста, переиспользование готового саммари). Пока саммари создаётся (это может занять десятки секунд), подпись кнопки меняется на «Саммари в процессе создания…» со спиннером. Результат показывается прямо в карточке: появляется саммари (в обоих положениях) и распознанный текст закона вместо сообщения «текст недоступен». Неудачи (лимит, нет текста, отказ модели, сбой) показываются сообщением внутри карточки; заголовок и ссылка на портал остаются; если текст закона при этом был получен — он показывается. Тексты сообщений WebApp — свои, короткие, без отсылок к командам бота.
- Новый HTTP-эндпоинт WebApp-сервера для запуска саммаризации; пользователь идентифицируется по подписанным Telegram данным запуска Mini-App (`initData`), которые сервер проверяет подписью токена бота. Без валидных данных (страница открыта не из Telegram) саммаризация не запускается.
- `/full_text` дополнительно отдаёт поле `summary` (обратно совместимо).
- Тизер дайджеста в чате больше не содержит кнопок «Сделать саммари №N» — только кнопку «📖 Дайджест». Вместо строки «Все документы — в полном списке по кнопке ниже» тизер (при заданном `WEBAPP_URL`) всегда заканчивается подсказкой «Саммари и полные тексты — в дайджесте по кнопке ниже. Там же можно сделать саммари для любого закона». Кнопки «№N» в уже отправленных дайджестах продолжают работать (обработчик остаётся). Без `WEBAPP_URL` в тизере нет ни кнопок, ни подсказки — саммари документа можно сделать только через `/summary`.
- Логика принудительной саммаризации (кеш → лимит → текст/OCR → саммари → сохранение → счётчик) выносится из `app/bot/handlers.py` в сервисную функцию, которую используют и бот, и WebApp. Сервис возвращает статус и данные, тексты сообщений формирует каждая точка входа; тексты бота не меняются.
- Готовое саммари из БД отдаётся до проверки месячного лимита — и в WebApp, и в боте. Сейчас бот при исчерпанном лимите отвечает «лимит исчерпан» даже для документа, у которого саммари уже сохранено; после изменения он покажет это саммари (без запроса к модели и без списания). Это единственное намеренное изменение поведения бота.

Не входит в изменение: одиночный режим WebApp (`/app?external_id=...`) — он открывается из сообщения, где саммари уже есть; состав документов и формат пунктов тизера (заголовок, саммари при наличии, ссылка) — меняются только кнопки и итоговая строка-подсказка.

## Capabilities

### New Capabilities
- (нет)

### Modified Capabilities
- `digest-notifications`: WebApp-дайджест показывает саммари в карточках и даёт кнопку «Сделать саммари» в карточках без саммари с выводом результата в той же карточке; тизер в чате теряет кнопки «Сделать саммари №N» и получает подсказку, что саммари делается в Mini-App; кнопки «№N» остаются рабочими только в ранее отправленных дайджестах.
- `force-summarization`: новая точка входа — Mini-App; идентификация пользователя по подписанным данным запуска Telegram, те же правила лимита/OCR/кеша, результат и неудачи возвращаются в страницу, а не сообщением бота. Месячный лимит не мешает получить уже сохранённое саммари (касается и бота).

## Impact

- `app/webapp/server.py` — новый `POST /summarize`, проверка `initData`, поле `summary` в `/full_text`, вёрстка/JS карточек дайджеста (саммари, кнопка, состояния загрузки/ошибки).
- `app/services/scheduler.py` — `_build_digest`: убрать кнопки «Сделать саммари №N», заменить итоговую строку на подсказку про саммари в Mini-App. `force_summarize_digest` в `app/bot/handlers.py` и его регистрация в `app/main.py` остаются для старых сообщений.
- `app/main.py` — в `start_webapp` передаётся `config` (нужны `TELEGRAM_BOT_TOKEN`, настройки GigaChat, лимит, `ADMIN_CHAT_IDS`, `REQUIRED_CHANNEL_ID`).
- Новый `app/services/force_summary.py` — общая функция принудительной саммаризации; `app/bot/handlers.py` — `_summarize_and_reply` становится тонким адаптером доставки над ней.
- БД: миграций нет — используются существующие `Article.summary`/`original_text` и `SummarizationUsage`.
- Внешние API: GigaChat вызывается по нажатию в Mini-App так же, как по кнопке в боте (в рамках того же лимита).
- Новых зависимостей нет (проверка подписи — `hmac`/`hashlib` из stdlib).
