## Why

При ручном тестировании один пользователь за раз получил 10 отдельных сообщений — pravo.gov.ru может опубликовать несколько документов за один цикл проверки, а рассылка сейчас шлёт по одному Telegram-сообщению на документ каждому подписчику. Это выглядит как спам и не масштабируется на дни с большим числом публикаций.

## What Changes

- Рассылка нового цикла проверки перестаёт слать уведомление сразу после обработки каждого документа. Вместо этого все новые документы цикла сперва обрабатываются (текст/саммари/классификация/сохранение), и только затем формируется рассылка.
- Для каждого пользователя отдельно считается, сколько документов этого цикла подошли под его `UserFilter` (с учётом `channel_verified`, если применимо к моменту деплоя `channel-subscription-gate`):
  - 1 подходящий документ → пользователь получает как сейчас: отдельное богатое сообщение (`_build_notification`, с кнопками).
  - 2+ подходящих документа → пользователь получает одно сообщение-дайджест: пронумерованный список (заголовок + краткое саммари на каждый документ), без кнопок на каждый пункт, по образцу форматирования `/latest`.
- Добавляется защита от превышения лимита Telegram в 4096 символов на сообщение (сейчас у `/latest` такой защиты нет, только жёсткий `LIMIT 10`; дайджест не ограничен по числу документов так же жёстко).

## Capabilities

### New Capabilities
- `digest-notifications`: правила группировки уведомлений о новых законах в одно сообщение на пользователя, когда за цикл проверки нескольким документам одновременно подходит его фильтр.

### Modified Capabilities
(нет — существующее правило "уведомление отправляется, если статья подходит под фильтр" не меняется по сути, меняется только группировка доставки; правило описано в `law-force-filter`, но его формулировка не требует изменений)

## Impact

- `app/services/scheduler.py` — `check_legislation_updates`/`_process_entry`/`_notify_users` перестраиваются: обработка документов цикла отделяется от рассылки, рассылка происходит один раз после обработки всех новых документов цикла.
- Новая функция форматирования дайджеста (переиспользует паттерн `_format_summary`/`_full_text_block` из `app/bot/handlers.py`, либо аналогичный код выносится в общее место).
- Не влияет на `/latest` (отдельная команда, свой независимый запрос).
