## Why

При ручном тестировании один пользователь за раз получил 10 отдельных сообщений — pravo.gov.ru может опубликовать несколько документов за один цикл проверки, а рассылка сейчас шлёт по одному Telegram-сообщению на документ каждому подписчику. Это выглядит как спам и не масштабируется на дни с большим числом публикаций.

## What Changes

- Рассылка нового цикла проверки перестаёт слать уведомление сразу после обработки каждого документа. Вместо этого все новые документы цикла сперва обрабатываются (текст/саммари/классификация/сохранение), и только затем формируется рассылка.
- Для каждого пользователя документы этого цикла, подходящие под его `UserFilter` (с учётом `channel_verified`), делятся на две группы:
  - **Важные** (уровень `CONSTITUTION`, `FKZ` или `FZ` — тот же набор, что уже определяет `is_important()`/`AUTO_LEVELS` в кодовой базе) — каждый доставляется отдельным индивидуальным сообщением (`_build_notification`, с кнопками), **независимо от того, сколько их найдено за цикл**. Логика: такие законы должны быть доступны немедленно, а не спрятаны за клик по MiniApp.
  - **Остальные** — действует прежнее правило по количеству: 1 подходящий → тоже индивидуальное сообщение; 2+ → одно сообщение-тизер с кнопкой «Дайджест».
- Тизер-сообщение дайджеста показывает до 3 случайно выбранных документов из «остальных» — каждый полным (без обрезки) заголовком, саммари (если оно уже получено — иначе строка саммари просто отсутствует) и ссылкой на портал — плюс общее число документов дайджеста. Если подходящих документов 3 или меньше, показываются все без случайного отбора. Кнопка «Дайджест» при этом ведёт в WebApp со **всеми** документами группы (не только теми тремя, что попали в текст) — полный список остаётся отдельным решением ниже.
- WebApp-аккордеон дайджеста показывает **все** подходящие «обычные» документы цикла для этого пользователя (не ограниченное текстом подмножество, как было раньше), с мягким техническим потолком на число документов в одной ссылке (защита от переполнения URL кнопки на «громкий» день) — остаток доступен через `/latest`. Заголовки секций по-прежнему обрезаются визуально (CSS `text-overflow: ellipsis`, полный заголовок виден при разворачивании), с короткой подсказкой про toggle-механику над списком.
- Принудительное саммари для документа без текста внутри дайджеста сознательно не реализуется (см. design.md, Risks/Trade-offs) — в отличие от одиночного уведомления (в т.ч. индивидуального для важного закона), где кнопка «Сделать саммари» уже есть.

## Capabilities

### New Capabilities
- `digest-notifications`: правила группировки уведомлений о новых законах в одно сообщение на пользователя, когда за цикл проверки нескольким документам одновременно подходит его фильтр.

### Modified Capabilities
- `content-viewing`: формулировка кнопки «Полный текст» расширена с «единственный закон» на «набор документов уведомления» — для дайджеста WebApp показывает несколько документов на одной странице в независимо сворачиваемых секциях, доступных по одной общей кнопке (delta-spec уже создан в `specs/content-viewing/spec.md` этой правки; дальнейших изменений формулировки эта ревизия не требует).

## Impact

- `app/services/scheduler.py` — `_notify_users_batch` делит подходящие пользователю документы цикла на важные (индивидуально, каждый отдельно) и остальные (1 → индивидуально, 2+ → тизер+кнопка); `_build_digest` строит тизер из до 3 случайно выбранных документов (`random.sample`) — полный заголовок, саммари при наличии, ссылка на портал — и общего числа документов дайджеста, плюс кнопку «Дайджест» со ссылкой на все документы группы в WebApp; прежняя пронумерованная текстовая версия дайджеста, `DIGEST_CHAR_LIMIT` и `_truncate_title`/`DIGEST_TITLE_LIMIT` остаются удалёнными — дайджест по-прежнему не пытается перечислить все документы в тексте.
- `app/webapp/server.py` — аккордеон (`?ids=...`) получает полный список подходящих «обычных» документов цикла (с мягким техническим потолком на число id в URL), а не подмножество, ограниченное прежней текстовой обрезкой; кнопка получает лейбл «Дайджест».
- Не влияет на `/latest` (отдельная команда, свой независимый запрос), на обработку отдельного документа (OCR/саммаризация) и на индивидуальный (не важный) режим просмотра WebApp (`?external_id=...`).
