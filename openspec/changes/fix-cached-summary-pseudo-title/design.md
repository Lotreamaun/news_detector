## Context

В `_summarize_and_reply` (`app/bot/handlers.py`) признак «заголовок известен» (`title_known`) сейчас вычисляется только в двух ветках: в успешном пути и в ветке `GigaChatError`. Там он равен `article is not None`. В ветке кэша (`cached.summary` задан) `_summary_final` вызывается без `title_known`, то есть с `True` по умолчанию. `_deliver_summary_failure` выбирает формат по `cached is not None`. Во всех трёх местах запись с `title == external_id`, созданная прошлым `/summary` вне ленты, считается «известной», и id уходит в `_format_summary` / `_summary_refused` жирным.

## Goals / Non-Goals

**Goals:**
- Одно правило «заголовок настоящий» для всех веток `_summarize_and_reply` и `_deliver_summary_failure`.

**Non-Goals:**
- Подтягивать настоящее название документа с pravo.gov.ru для законов не из ленты.
- Менять отображение в WebApp и `/notify_me`.
- Мигрировать уже сохранённые записи с `title == external_id`.

## Decisions

**1. Признак псевдозаголовка — `not title or title == external_id`.**
Небольшой хелпер (например, `_has_real_title(article, external_id) -> bool`) рядом с `_summary_final`. Все ветки получают `title_known` из него, а не из `is not None`.
*Альтернатива:* добавить в `Article` колонку-флаг «заголовок неизвестен». Отклонена: нужна миграция схемы, а та же информация уже однозначно видна из данных (так запись пишет только `/summary` вне ленты).
*Альтернатива:* получать настоящий заголовок через API портала. Отклонена для этого фикса: в `rss_parser` нет запроса метаданных по одному id, это новая сетевая зависимость и новый режим отказа. Это отдельная фича, а не багфикс.

**2. `_deliver_summary_failure` ветвится по «заголовок настоящий», а не по `cached is not None`.**
Запись с псевдозаголовком получает `_summary_refused_plain`, то есть тот же вид, что и неизвестный закон. Так закрываются все три ветки неудачи (лимит / нет текста / generic) одним изменением.

**3. Ветка кэша передаёт `title_known` в `_summary_final`.**
При `title_known=False` `_summary_final` уже выводит «саммари + `id: …` + ссылка + кнопка», и это ровно формат первого запроса. Новая разметка не нужна.

## Risks / Trade-offs

- [Настоящий заголовок, совпадающий с id] → на практике невозможен: заголовки из ленты — это текст названия акта, а не 16-значный номер.
- [Запись с псевдозаголовком позже встречается в ленте] → скорее всего, не дойдёт до обновления заголовка: шедулер фильтрует ленту по уже известным `external_id`. Это существующее поведение, фикс его не меняет и не ухудшает. Отображение останется корректным: без жирного id.
