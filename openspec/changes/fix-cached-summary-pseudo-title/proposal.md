## Why

Предыдущий фикс (`fix-summarize-failure-fallback`) научил бота не показывать `external_id` жирным «псевдозаголовком», когда закон запрошен через `/summary` впервые и его нет в ленте. Но в этом случае бот сохраняет запись `Article` с `title = external_id`. Поэтому **повторный** `/summary <тот же id>` находит эту запись в БД, считает закон «известным» и выводит сохранённое саммари в формате уведомления: *жирный заголовок = id документа* — саммари — «Читать на портале» — кнопка «Полный текст». Получается то же вводящее в заблуждение сообщение, которое прошлый фикс должен был убрать; оно лишь сдвинулось на второй запрос.

## What Changes

- Критерий «заголовок закона известен» в принудительной саммаризации меняется. Раньше он звучал как «запись `Article` существует», теперь — «запись существует **и** её заголовок настоящий». Заголовок не настоящий, если он пуст или совпадает с `external_id` (это псевдозаголовок, который `/summary` сохраняет для законов не из ленты).
- Ветка переиспользования сохранённого саммари (повторный `/summary`, кнопка) для записи с псевдозаголовком выводит тот же формат, что и при первом запросе: саммари + строка `id: …` + ссылка на портал + кнопка «Полный текст». Жирного id больше нет.
- Сообщения о неудаче (лимит исчерпан / текст недоступен / непредвиденная ошибка) для записи с псевдозаголовком строятся как для неизвестного закона: простое служебное сообщение с причиной, `external_id` и ссылкой, без жирного id.
- Успешная саммаризация и отказ LLM для записи с псевдозаголовком — например, созданной прошлой неудачной попыткой, когда LLM отказалась, — тоже не выводят id жирным.
- Схема БД и способ сохранения записи не меняются: `title = external_id` по-прежнему пишется для законов не из ленты, меняется только то, как такая запись отображается.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `manual-summary-request`: новое требование: сохранённый псевдозаголовок (`title` пуст или равен `external_id`) никогда не показывается как заголовок закона — ни при переиспользовании сохранённого саммари, ни в сообщениях о неудаче, ни при повторной саммаризации.

## Impact

- `app/bot/handlers.py`: `_summarize_and_reply` (ветка кэша, успешный путь, ветка `GigaChatError`), `_deliver_summary_failure`. Возможен небольшой хелпер для проверки «заголовок настоящий».
- Точки входа: `/summary`, кнопка «Сделать саммари» (в том числе в дайджесте) — у всех общий код.
- Вне скоупа: WebApp (`app/webapp/server.py` показывает `title || id` в своём заголовке) и `/notify_me` — отдельные места вывода, баг в них не заявлен.
- Миграций и обратной несовместимости нет.
