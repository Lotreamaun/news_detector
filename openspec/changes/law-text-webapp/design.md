## Context

См. proposal.md (Why): распознанный при OCR полный текст уже сохраняется в `original_text` (Article), но пользователю не показывается — только саммари и ссылка на портал. Telegram WebApp открывается только по HTTPS, поэтому Mini-App вынесен из `improve-content-formatting` в отдельную фичу.

Текущее состояние кода:
- Бот на PTB + SQLAlchemy async; `Config` — frozen dataclass, загрузка в `Config.load()`. Хендлеры читают `context.bot_data["config"]`.
- `_deliver` (handlers.py) — единая точка доставки результата (правит исходное сообщение при кнопке или шлёт новое); сейчас без reply_markup.
- `_build_notification` (scheduler.py) — собирает текст уведомления + кнопку «Сделать саммари».
- Откаченный ранее `app/webapp/` (aiohttp: GET `/app` и GET `/full_text?external_id=...`) удалён; реализуем заново по этому дизайну.

## Goals / Non-Goals

**Goals:**
- Лёгкий внутренний HTTP-сервер WebApp: HTML-страница (фронтенд Mini-App) + API полного текста по `external_id`.
- Кнопка «Полный текст» (WebApp-кнопка, `web_app=WebAppInfo(url=...)`) поверх существующих кнопок в доставке саммари и в уведомлениях.
- Пометка «распознано с помощью ИИ» (дисклеймер) и ссылка на оригинал внутри Mini-App.
- Конфигурация через `.env` (`WEBAPP_HOST`/`WEBAPP_PORT`/`WEBAPP_URL`); без заданного `WEBAPP_URL` кнопка не добавляется (фича полностью отключается без блокировки остального бота).
- Минимум новых зависимостей, не блокировать основной цикл бота.

**Non-Goals:**
- Не заменяем ссылку на оригинал портала — она остаётся всегда (требование content-formatting).
- Не храним текст заново: используем существующий `original_text`; миграций БД нет.
- Не реализуем полноценный HTTPS-терминатор, auth-провайдеров Telegram (initData) и store-хостинг WebApp — `WEBAPP_URL` публикуется внешним прокси/хостингом.
- Не делаем OCR и не генерируем текст на лету в WebApp.
- Не трогаем `/latest` (там ссылка на оригинал уже есть; WebApp-кнопка не нужна — только в точечных сообщениях с саммари и уведомлениях).

## Decisions

### 1. Фреймворк сервера — aiohttp

Внутренний сервер на aiohttp, запускается в event loop бота (после `Application.run_polling` стартует свой loop; поднимаем aiohttp на том же loop через `asyncio.create_task`/`loop.create_server` в hook). Альтернативы: FastAPI+uvicorn (тяжелее, отдельный процесс/порт настройки), стандартный `http.server` (треды, без async). aiohttp лёгкий, async, хорошо интегрируется с существующим asyncio.

### 2. Маршруты WebApp-сервера

- `GET /app?external_id=<id>` — HTML-страница Mini-App (фронтенд на чистом JS, без сборки): читает `external_id` из query, грузит текст с API, рендерит.
- `GET /full_text?external_id=<id>` — JSON `{title, url, text, is_text_available}` (текст из `original_text`; `is_text_available=false`, если он пуст). Оба маршрута одностраничные, без SPA-роутинга.

### 3. Кнопка «Полный текст»

`WEBAPP_URL` (публичный HTTPS) + `article.external_id` → `WebAppInfo(url=f"{WEBAPP_URL}/app?external_id={external_id}")`. Кнопка-строка добавляется в `InlineKeyboardMarkup` поверх существующей: в `_deliver` (все места доставки результата саммари) и в `_build_notification`. Если `WEBAPP_URL` пуст — кнопку не строим, ничего не ломаем. Ссылка на оригинал остаётся в тексте.

### 4. Дисклеймер в Mini-App

Фронтенд всегда отображает пометку «⚠️ Текст распознан с помощью ИИ, возможны ошибки» над текстом и ссылку на оригинал (из API). Это соответствует требованию content-formatting о честном дисклеймере.

### 5. Старт/стоп сервера

Старт сервера привязан к `post_init` (после `_register_commands`), graceful shutdown в `post_shutdown`. При недоступности порта — логировать предупреждение и продолжать (бота не валим). `WEBAPP_HOST/PORT` — bind внутреннего адреса, `WEBAPP_URL` — публичный внешний адрес (может смотреть на тот же порт через прокси/домен).

## Risks / Trade-offs

- [WebApp-кнопка не открывается по не-HTTPS] → `WEBAPP_URL` обязан быть HTTPS (документируем в README/.env); при неверном/пустом значении кнопка просто не добавляется, фича деградирует безопасно.
- [Внутренний HTTP-сервер упрётся в синхронные запросы к БД] → обращения к БД делаем через существующий async session_maker, не блокируем event loop бота.
- [Полный текст огромный (длинный закон)] → отдаём одним JSON; фронтенд рендерит с overflow скроллом; при необходимости — обрезка/пагинация, но это не требуется спецификацией.
- [aiohttp-сервер конфликтует с PTB lifecycle] → сервер стартует в hook после запуска бота, шатдаун в `post_shutdown`; при падении сервера бот продолжает работу.
- [Безопасность: эндпоинт по external_id публичен] → текст — публичные законы, авторизация не требуется; валидируем формат `external_id`, гоняем через параметры URL (URL-safe escaping).

## Migration Plan

- Никаких миграций БД (используется существующий `original_text`).
- Внедрение: (1) конфиг + aiohttp-сервер + API, (2) фронтенд-страница с дисклеймером, (3) кнопка в `_deliver`/`_build_notification`, (4) документация `.env.example`/README.
- Роллбэк: убрать `WEBAPP_URL` из `.env` (кнопка исчезает) или отключить старт сервера — остальные функции бота не зависят от WebApp.

## Open Questions

- Точный вид фронтенда (тема/шрифты Telegram-подобные) — решается при реализации, не меняет спецификацию.
- Нужна ли пагинация для очень длинных документов — решается при реализации, спецификация этого не требует.
