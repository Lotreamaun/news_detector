## Context

«Тренд» считает `stats.trend()` (`app/services/stats.py`): 10 рядов, у каждого — столбец-дата, условия и агрегат (`COUNT(*)` или `COUNT(DISTINCT telegram_id)` у активных). Внутренний `weekly()` раскладывает их по неделям через `_bucket` (`julianday`). Ряды из журнала превращаются в `None` для недель целиком до `MIN(events.at)` (`from_journal`). Ряд подборки — `min(v, 1)` по `WeeklyDigestRun.period_end`. В ответе также лежит `feedback` (`feedback_summary`) для панели «Оценка подборки».

API — `GET /admin/api/stats?view=pulse|trend` (`app/webapp/admin.py`, `handle_stats`). Фронт (`app/webapp/static/admin.html`) держит кэш `sv[view]`, грузит `loadStats(view)`, на каждый ответ полностью пересобирает `#stats-main` через `renderStatsTab` (сохраняется только прокрутка). Переключатель «Пульс | Тренд» (`#seg`) статичный, в шапке; выбор хранится в `localStorage` (`adminStatsKind`). Спарклайн `spark()` — SVG 188×36, столбики 12 px с промежутком 4 px; число прошлой недели доступно только в `<title>` (наведение).

Требования — в `specs/bot-activity-stats/spec.md` этого change.

## Goals / Non-Goals

**Goals:**
- Один источник определений рядов для недельного вида и для сравнения, чтобы подсчёт в них не мог разойтись.
- Сервер отдаёт только сырые значения двух отрезков; процент, стрелки и цвет считает фронт (это представление).
- Нажатие на столбик не перерисовывает вкладку: меняется только строка значения и выделение в своём ряду.

**Non-Goals:**
- Новые индексы, кэширование или предрасчёт: объёмы маленькие, всё по-прежнему считается при запросе.
- Общий выбор недели для всех рядов сразу (столбец-курсор через все графики).
- Перенос переключателя режимов в статичную шапку.

## Decisions

### 1. Определения рядов — одна функция, два способа агрегации

В `stats.py` выносится `_trend_series(config)` — список описаний `{key, title, column, where, value, journal}` в нынешнем порядке. `value` — агрегат (по умолчанию `func.count()`), `journal=True` у рядов из журнала событий. Условия переносятся из нынешнего `trend()` как есть, включая `_not_admin` и `events_where`.

- `trend()` проходит по списку и для каждого вызывает прежний `weekly()`. `from_journal` применяется к рядам с `journal=True`, `min(v, 1)` — к `digest`, как сейчас. Ответ `trend` не меняется.
- Новая `compare(session_maker, config, unit, now=None)` для каждого ряда делает два `SELECT value WHERE column >= start AND column < end AND where…` — по одному на отрезок. Всего 20 маленьких агрегатов, `events.at` проиндексирован.

Альтернативы:
- скопировать 10 определений во вторую функцию — проще читать, но тексты пояснений общие для обоих видов, а расхождение подсчёта легко пропустить. Это тот случай, когда общее место оправдано;
- одним запросом на ряд через `SUM(CASE …)` / `COUNT(DISTINCT CASE …)` — вдвое меньше запросов, но сложнее читать; выигрыш для панели, которую открывают руками, не нужен.

### 2. Отрезки сравнения — чистая функция

`compare_periods(unit, now) -> (cur_start, cur_end, prev_start, prev_end)` в `stats.py`, все моменты в aware UTC:
- `week`: `cur_start` — полночь понедельника по Москве (`portal_today` − `weekday()`, `_msk_midnight`), `cur_end = now`, `prev_start = cur_start − 7 дней`, `prev_end = now − 7 дней`;
- `month`: `cur_start` — полночь 1-го числа текущего месяца по Москве, `prev_start` — полночь 1-го числа прошлого месяца, `prev_end = min(prev_start + (now − cur_start), cur_start)`.

Длина отрезка считается точно до момента запроса, а не до конца дня: сегодняшний неполный день сравнивается с тем же неполным днём прошлого периода. В Москве нет перехода на летнее время, поэтому разница UTC-моментов равна разнице московского времени.

Альтернатива: «до конца сегодняшнего дня» в обоих отрезках. Отклонена: утром прошлый отрезок уже содержит весь день, а текущий — его начало, и сравнение снова занижает текущий период.

### 3. «Нет данных» в сравнении строже, чем в недельном виде

В «Неделях» `None` ставится, только если неделя целиком раньше начала журнала. В сравнении значение ряда из журнала — `None`, если журнала нет или `tracking_since > start` отрезка: частично покрытый отрезок дал бы ложный рост. Ряды из всей истории БД (регистрации, акты, подборка) не затрагиваются. Очистка журнала старше 365 дней на это не влияет: самый ранний отрезок — начало прошлого месяца.

### 4. Ответ API

`GET /admin/api/stats?view=compare_week|compare_month`. `handle_stats` выбирает построитель по словарю `{"pulse": …, "trend": …, "compare_week": partial(stats.compare, unit="week"), "compare_month": partial(stats.compare, unit="month")}`. Неизвестный `view` по-прежнему даёт 400.

```json
{
  "generated_at": "…Z",
  "tracking_since": "…Z" | null,
  "unit": "week" | "month",
  "current":  {"start": "…Z", "end": "…Z"},
  "previous": {"start": "…Z", "end": "…Z"},
  "series": [{"key": "registrations", "title": "Регистрации", "previous": 12, "current": 18}, …],
  "feedback": […]
}
```

`feedback` кладётся и сюда, чтобы панель «Оценка подборки» рисовалась в любом режиме из одного ответа. Ряд `digest` в сравнении — число отправленных подборок без `min(v, 1)`; в режиме недель фронт показывает его как «да» / «нет».

Отдельный параметр `?compare=` к `view=trend` отклонён: у сравнения другая форма ответа, и это отдельный кэш на фронте.

### 5. Фронт: режим «Тренда» и кэш

- Новые `trendMode` (`weeks` | `compare_week` | `compare_month`, `localStorage` `adminTrendMode`, неизвестное значение → `weeks`) и `statsView()`: при `pulse` — `'pulse'`, при `weeks` — `'trend'`, иначе — `trendMode`. `sv` получает слоты `compare_week` / `compare_month`. `statsStatus`, `updateStatsClock` и проверка в конце `loadStats` смотрят на `sv[statsView()]` вместо `sv[statsKind]`.
- `setStatsKind('trend')` грузит `statsView()`. Новая `setTrendMode(mode)`: сохранить, перерисовать (из кэша, если он есть), `loadStats(statsView(), true)`. Каждый выбор режима обновляет данные, как сейчас открытие «Тренда».
- Переключатель режимов рисуется первым элементом `trendView` / `compareView`: `.seg.seg-wide` (на всю ширину, кнопки `flex: 1`, текст может переноситься в две строки, `min-height: 40px`), `role="tablist"`, кнопки `role="tab"` с `data-key="mode:<режим>"`. Подписи «Недели», «Неделя к неделе», «Месяц к месяцу». Так как вкладка пересобирается, после `renderStatsTab` фокус возвращается на кнопку выбранного режима, если переключение было из неё (тот же приём, что у `hintOpener`).
- Пока открыта шторка пояснений, страница `inert` (`showModal`), поэтому переключение режимов при открытой шторке недоступно без отдельного кода.

### 6. Фронт: таблица сравнения

`compareView(d)` = переключатель + `block(<«Неделя к неделе» | «Месяц к месяцу»>, <подпись отрезков>, rows, 'trend.compare_' + unit)` + `feedbackBlock` + `allHintsLink('trend')`.

- Подпись отрезков: «Сейчас: пн 26.10 00:00 – ср 28.10 15:00 · Было: пн 19.10 00:00 – ср 21.10 15:00». Если прошлый отрезок обрезан концом месяца (`previous.end == current.start`), пишется «Было: весь прошлый месяц, 01.02–28.02», чтобы не показывать «до 01.03 00:00».
- Строка ряда (`.trend-row`): слева название через `hintLink` (ключ `trend.<key>`), справа значения «12 → 18» (`tabular-nums`) и изменение. На узком экране правая часть переносится под название, как сейчас спарклайн.
- Изменение: `d = cur − prev`. Если `d = 0` — «=». Иначе «▲ +6» / «▼ −6» (настоящий минус U+2212) и, при `prev > 0`, «+50%» — `Math.round(d / prev * 100)`. Если одно из значений `null` — «нет данных» на его месте и без изменения. Для `digest` при `unit = week` значения «да» / «нет», без изменения.
- Цвет: словарь `TREND_BETTER = {registrations: 1, active: 1, opens: 1, summaries: 1, blocks: -1, check_failures: -1}`. `sign(d) * better > 0` → `.cmp-good` (зелёный, `#0f5132` / тёмная тема `#75b798`), `< 0` → `.cmp-bad` (те же цвета, что `.upd.warn`: `#842029` / `#ea868f`). Ряды вне словаря — `var(--muted)`.
- Доступность: у изменения `aria-label` словами («рост на 6, плюс 50 процентов» / «падение на 1» / «без изменений»), стрелки и цвет — `aria-hidden` дубли.

### 7. Фронт: нажимаемые столбики

- Размеры спарклайна: столбик 14 px, промежуток 6 px, высота 40 → `viewBox` 234×40, CSS 234×40 px. Зона нажатия — прозрачный `rect` поверх каждого столбика на всю высоту и шириной 20 px (столбик + промежуток), `data-i=<индекс>`. Один обработчик `click` на `svg` берёт `e.target.dataset.i`. `<title>` переезжает на зону нажатия, поэтому подсказка мышью на компьютере остаётся.
- Состояние: `trendPick = {<key>: <index>}`, по умолчанию индекс текущей недели (последний). Повторное нажатие выбранного столбика (если он не текущий) возвращает к текущей неделе. После успешной загрузки `trend` `trendPick` очищается: недели сдвигаются.
- Обновление на месте: нажатие меняет классы столбиков своего `svg` и текст своей строки `.trend-now`, без `renderStatsTab`. Поэтому не сбрасываются прокрутка и фокус. Когда выбрана не текущая неделя, у выбранного столбика класс `.sel` (полная непрозрачность), остальные столбики ряда — `opacity: .35`; у пунктирного «нет данных» при выборе сплошная обводка цветом акцента.
- Строка: текущая неделя — «эта неделя: **N**» (как сейчас), другая — «неделя с 12.10: **N**» (`mskDay`), без данных — «… нет данных».
- Клавиатура и диктор: `svg` получает `tabindex="0"` и `role="slider"`, `aria-label` — название ряда, `aria-valuemin=1`, `aria-valuemax=12`, `aria-valuenow` — номер выбранной недели, `aria-valuetext` — тот же текст, что в строке. ← / → двигают выбор, Home / End — к первой / текущей, Esc — к текущей. Изменение `aria-valuetext` у слайдера диктор объявляет сам. Видимый фокус — `outline` как у `.hint-link`.

Альтернативы: `role="img"` с `tabindex` и обработкой клавиш — фокусируемая картинка с поведением противоречит ARIA; 12 фокусируемых `rect` на ряд — 120 остановок Tab на вкладке. Выбор одной позиции из упорядоченных стрелками — это ровно шаблон слайдера.

### 8. Пояснения

- Тексты `trend.*` в `HINTS` переписываются без «за неделю»: «за период». Сам период описывают `HINT_TREND_NOTE` и пояснения к сравнению. Уточнения: у `trend.active` — «человек считается один раз за период»; у `trend.with_summary` — что у более раннего отрезка было больше времени получить саммари; у `trend.digest` — «да/нет» для недель и число подборок для месяца; у журнальных рядов — «нет данных» для недель и отрезков, начавшихся до начала журнала.
- Новые ключи `trend.compare_week` и `trend.compare_month`: отрезки (с понедельника / с 1-го числа до момента открытия против такого же отрезка прошлого периода; для месяца — не дальше его конца), почему одинаковой длины (неполный период иначе всегда выглядит падением), процент от прошлого значения с округлением, без процента при нуле, «нет данных», цвет только у рядов с понятным направлением.
- `HINT_TREND_NOTE` дополняется одной фразой о режимах сравнения. `openAllHints('trend')` в режиме сравнения добавляет первой группу «Сравнение» с ключом текущего режима. `HINT_GROUPS.trend` не меняется.

## Risks / Trade-offs

- [Активные за месяц — разные люди за месяц, их нельзя сложить из недель] → значение месяца считается отдельным `COUNT(DISTINCT)` по отрезку, а не суммой недель; так и написано в пояснении.
- [«Из них с саммари» систематически выше у прошлого отрезка: у его актов было больше времени] → сказано в пояснении ряда; ряд без цвета.
- [Мелкие значения дают громкие проценты: 1 → 3 = +200%] → разница числом всегда стоит рядом с процентом, а при нуле процент не показывается.
- [Зона нажатия 20 px уже рекомендуемых 44 px] → она занимает всю высоту графика; 12 столбиков не помещаются шире на ширине телефона без переноса. Если окажется неудобно, проще увеличить высоту `.spark`, чем менять схему.
- [Перенос подписей переключателя в две строки на узком экране] → допускается намеренно (`seg-wide`, `min-height: 40px`); сокращения вроде «Н/Н» хуже читаются.
- [Рефакторинг `trend()` может незаметно поменять недельные цифры] → в задачах сверка ответа `view=trend` до и после на одной и той же БД.

## Migration Plan

Только код: без миграций БД и без новых переменных `.env`. Деплой — обычная пересборка контейнера на Dockhost. Откат — предыдущий образ. Сохранённый в `localStorage` режим, неизвестный старой версии, она просто проигнорирует.
