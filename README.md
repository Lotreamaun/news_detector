# ⚖️ News Detector — LegalTech-сервис для парсинга законов

Сервис автоматического мониторинга и анализа законов РФ. Бот парсит документы с портала `pravo.gov.ru`, делает саммари и присылает уведомление.

## 🚀 Функциональность

### Первый релиз (MVP)
- **Автоматически парсит** документы с портала pravo.gov.ru (настраиваемый интервал, по умолчанию 15 минут)
- **Делает саммари** с помощью GigaChat API
- **OCR-фоллбэк** для «важных» актов (ФКЗ): если текст ещё не готов на портале, GigaChat распознаёт PDF со сканов
- **Присылает пуш-уведомление** пользователю о новом законе: саммари + ссылка на оригинал (при сбое — ссылка без саммари)

## 🏗 Архитектура

```
Пользователь → [Telegram Bot (PTB)] → [Ядро приложения] → [База данных (SQLite)]
                                             ↓
        [Сервисы: RSS-парсер · Саммаризатор · Планировщик · Клиент GigaChat]
                                             ↓
                    [Внешние API: pravo.gov.ru, GigaChat]
```

### Поток данных:
1. **Планировщик** (PTB JobQueue) запускает проверку каждые `CHECK_INTERVAL_MINUTES` (по умолчанию 15 мин) и сразу при старте бота
2. **rss_parser** получает список документов дня (JSON API `publication.pravo.gov.ru`) и превращает каждый в `FeedEntry`
3. Новые документы (которых нет в таблице **articles** по `external_id`) обрабатываются по цепочке: текст с `actual.pravo.gov.ru` → если текста нет, а акт «важный» — OCR через GigaChat → саммари
4. **summarizer** передаёт текст в GigaChat и получает краткую выжимку
5. Результат сохраняется в **articles**, уведомление уходит всем активным **users**

## 🧩 Модули и ответственность

### 1. **app/main.py** - Точка входа
- Запуск всего приложения
- Инициализация всех компонентов
- Обработка graceful shutdown

### 2. **app/bot/handlers.py** - Telegram интерфейс
- Обработка команд бота (`/start`, `/test`)

### 3. **app/core/config.py** - Конфигурация
- Загрузка переменных окружения из `.env`
- Централизованное хранение настроек
- Валидация обязательных параметров

### 4. **app/core/database.py** - Работа с БД
- Подключение к базе данных
- Создание сессий для работы с БД
- Инициализация таблиц

### 5. **app/models/** - Структура данных
- **user.py**: Пользователи Telegram (id, username, подписки)
- **article.py**: Законы и документы (название, текст, саммари, дата)

### 6. **app/services/rss_parser.py** - Парсер законов
- Загрузка списка документов дня (JSON API publication.pravo.gov.ru)
- Извлечение полного текста закона (редакции actual.pravo.gov.ru, HTML → Plain Text)
- OCR-фоллбэк через GigaChat для «важных» актов при отсутствии текста

### 7. **app/services/gigachat.py** - Клиент GigaChat
- Авторизация (access-токен), список моделей
- Загрузка/удаление файлов в хранилище (для OCR)
- Запросы chat completion (для саммари и распознавания)

### 8. **app/services/summarizer.py** - Анализ текста
- Создание краткого саммари (140-280 символов)
- Обрезка и форматирование текста

### 9. **app/services/scheduler.py** - Планирование
- Периодическая проверка ленты (интервал из конфига, по умолчанию 15 мин)
- Оркестрация: фильтр новых → текст → саммари/OCR → сохранение → рассылка
- Fallback-уведомление со ссылкой на оригинал при любой ошибке

## ⚡ Быстрый запуск на локалхосте (личный чек-лист)

Предполагается: macOS, Python 3.14+, репозиторий уже склонирован.

1. **Создать и активировать виртуальное окружение:**
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   ```

2. **Установить зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Настроить `.env`:**
   ```bash
   cp .env.example .env
   ```
   Заполнить обязательно:
   - `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
   - `GIGACHAT_AUTH_KEY` — в формате `Basic <секретный_код>` (личный кабинет на [developers.sber.ru](https://developers.sber.ru))
   - `DATABASE_URL` — оставить как в шаблоне (`./data/news_detector.db`)

4. **Создать папку для БД** (если `DATABASE_URL` ведёт в `./data`):
   ```bash
   mkdir -p data
   ```

5. **Проверить конфигурацию без запуска бота:**
   ```bash
   python -c "from app.core.config import Config; print(Config.load())"
   ```
   Должен вывестись объект конфига, а не `ConfigError`.

6. **Запустить:**
   ```bash
   python -m app.main
   ```

7. **Проверить в Telegram:**
   - `/start` — регистрация пользователя в БД
   - `/test` — smoke-тест GigaChat (токен, список моделей, ответ)

8. **Остановить:** `Ctrl+C` — graceful shutdown, соединения с БД закрываются.

> **Из РФ:** если бот не подключается к Telegram (`Timed out`, `NetworkError`) —
> включить VPN или указать в `.env` рабочий прокси `TELEGRAM_PROXY_URL`
> (формат и подводные камни — в разделе «⚙️ Запуск» ниже).

Логи пишутся в консоль и в файл `app.log` (`tail -f app.log`).

### Требования
- **Python 3.14+** (асинхронный код, `aiosqlite`)
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)
- Ключ авторизации GigaChat (`GIGACHAT_AUTH_KEY`) — в личном кабинете на [developers.sber.ru](https://developers.sber.ru)

### Шаги

1. **Клонировать репозиторий и перейти в папку проекта:**
   ```bash
   git clone <url-репозитория>
   cd news_detector
   ```

2. **Создать и активировать виртуальное окружение:**
   ```bash
   python3 -m venv venv
   source venv/bin/activate   # macOS / Linux
   # venv\Scripts\activate    # Windows (PowerShell)
   ```

3. **Установить зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Настроить переменные окружения:**
   ```bash
   cp .env.example .env
   ```
   Открыть `.env` и заполнить обязательные поля:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather
   - `DATABASE_URL` — оставить `sqlite+aiosqlite:///./data/news_detector.db` или изменить путь
   - `GIGACHAT_AUTH_KEY` — ключ в формате `Basic <секретный_код>`
   Остальные параметры можно оставить по умолчанию.

   > **Из РФ без прокси бот не подключится к Telegram:** `api.telegram.org`
   > заблокирован. Укажите в `.env` рабочий прокси:
   > `TELEGRAM_PROXY_URL=http://user:pass@host:port`. Пусто — без прокси.

5. **Создать папку для БД** (если `DATABASE_URL` ведёт в `./data`):
   ```bash
   mkdir -p data
   ```

6. **Запустить приложение:**
   ```bash
   python -m app.main
   ```

После старта бот поднимется, создаст таблицы в SQLite и начнёт обрабатывать команды.
Логи пишутся в консоль и в файл `app.log`.

Вместе с ботом стартует встроенный **WebApp (Mini-App)** для просмотра полного
текста закона (HTTP-сервер на `WEBAPP_HOST:WEBAPP_PORT`). Кнопка «📖 Полный
текст» в сообщениях бота открывает этот WebApp. Для локальной разработки
достаточно значений по умолчанию (`http://127.0.0.1:8080`), для продакшена
нужен HTTPS-домен — он задаётся в `WEBAPP_URL` (Telegram требует HTTPS для
WebApp). Если `WEBAPP_URL` пуст — кнопка не показывается, остальной функционал
бота (саммари, уведомления) продолжает работать.

### Команды бота
- `/start` — регистрация пользователя в БД (уникальный `telegram_id`) + приветствие
- `/test` — smoke-тест GigaChat: получение токена, список моделей и короткий запрос

### Проверка конфигурации (без запуска бота)
```bash
python -c "from app.core.config import Config; print(Config.load())"
```
Команда выведет объект конфигурации или поднимет `ConfigError` с описанием проблемы.

## 🐳 Деплой на Dockhost

Бот упаковывается в один Docker-образ (`Dockerfile`) и поднимается через
`docker-compose.yml` (один сервис `bot`, БД и логи — на смонтированных
volume `./data` и `./logs`, чтобы переживать пересоздание контейнера).
Код `app/` для деплоя не меняется — только упаковка и прод-конфиг.

### 1. Создать контейнер/проект на Dockhost

В панели Dockhost создать проект из этого Git-репозитория (сборка по
`Dockerfile` в корне). Локально образ проверяется так же, как будет
собираться на сервере:
```bash
docker build -t news-detector .
```

### 2. Перенести `.env` на сервер вручную

`.env` в репозиторий не коммитится и не попадает в образ (см. `.dockerignore`).
Создать его на сервере вручную (`.env.example` — шаблон). Обязательные для
прода значения:
- `TELEGRAM_BOT_TOKEN`, `DATABASE_URL=sqlite+aiosqlite:///./data/news_detector.db`,
  `GIGACHAT_AUTH_KEY` (с префиксом `Basic `) — как для локального запуска.
- `TELEGRAM_PROXY_URL=<рабочий прокси>` — сервер Dockhost в РФ, `api.telegram.org`
  напрямую недоступен.
- `WEBAPP_HOST=0.0.0.0` — обязательно для контейнера, дефолтный `127.0.0.1`
  недоступен снаружи.
- `WEBAPP_URL=<динамический домен Dockhost>` (HTTPS) — чтобы кнопка «Полный
  текст» открывала WebApp.

### 3. Настроить internal route в панели Dockhost

Привязать динамический домен к сетевому сервису контейнера на порт `8080`
(порт объявлен как `EXPOSE 8080` в `Dockerfile` и как `WEBAPP_PORT=8080` в
`.env`). Если панель Dockhost требует отдельно указать порт контейнера для
маршрутизации (помимо `EXPOSE`) — донастроить на месте при первом деплое.

### 4. Запустить

```bash
mkdir -p data logs
docker compose up -d --build
```
`restart: unless-stopped` в `docker-compose.yml` перезапускает процесс при
аварийном завершении без ручного вмешательства.

### 5. Смоук-тест после первого деплоя

- `/start` — регистрация проходит, бот отвечает.
- `/latest` — отдаёт последние ФКЗ/ФЗ за 30 дней.
- `/summary` — принудительное саммари по ссылке/id работает.
- Кнопка «📖 Полный текст» открывает WebApp по HTTPS-домену Dockhost.
- В логах (`docker compose logs bot` или `./logs/app.log`) нет ошибок
  подключения к Telegram — значит `TELEGRAM_PROXY_URL` реально пробивает
  блокировку `api.telegram.org` из РФ.
- `is_first_run` подавил рассылку старых законов всем подписчикам (бот не
  заспамил чат сразу после первого запуска на пустой БД).

## 🔧 Разработка

### Добавление новой команды в бота:
1. Добавить обработчик в `app/bot/handlers.py`
2. Зарегистрировать обработчик в `app/main.py`
3. При необходимости добавить клавиатуру

### Добавление новой модели:
1. Создать файл в `app/models/`
2. Наследоваться от `Base` из `app.core.database`
3. Импортировать модель в `app/core/database.py` для создания таблиц

### Добавление нового сервиса:
1. Создать файл в `app/services/`
2. Реализовать бизнес-логику
3. Импортировать и использовать в основном потоке
